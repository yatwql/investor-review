# 去重锚点存储治理设计（采样 / 保留期 / 体积上限 / 月分片）

> **关联任务**：`rf-938` ~ `rf-943`（详见 `docs/managements/review-findings.md`）
> **状态**：已实施
> **关联文档**：`technical.md`「体积治理」、`developer-guide.md`「去重锚点默认采集、写侧零读取」

## 1. 基线诊断（2026-10-28 实测）

`data/calibration/dedup_anchors.jsonl` 是 append-only 的边界案例采集文件，唯一消费者是去重阈值校准工具。

| 指标 | 实测值 | 设计含义 |
|---|---|---|
| 体积 / 行数 | 34.0 MB / 94,706 行 | 单文件累积，无体积上限 |
| 唯一键 | 94,706（重复率 **0.000**） | 「每 key 最新」这一类去重条件不产生任何裁剪 |
| 最旧记录 | 2026-08-30（59 天） | 120 天保留期大于数据龄，保留期条件同样不触发 |
| 增长 | 均值 1,754 行/天（≈0.63 MB/天），峰值 5,705 行（10-26） | 约 3 个月到 100 MB |
| `same_src` 占比 | 57,899 条（**61.1%**），`ratio` 恒 0.0、`merged` 恒 false | 校准信息量极低，主导体积 |
| 近门槛样本（ratio 0.55~0.85） | 5,433 条（5.7%） | 真正可用的校准样本规模 |
| 无规则指纹的行 | 20,306 条（21%） | 无法归因到任何规则时代 |

**两条结论**：① 三重条件（每 key 最新 / 保留期 / 体积）在设计上都存在，但基线数据下**一个都不触发**，体积无确定性上限；② 采样构成与规则时代标注一起决定了校准口径是否可信。

## 2. 设计

### 2.1 同源分支采样

`same_src` 分支服务「同一源合并阈值」校准，其 2~5 bigram 区间样本极密，`ratio` 为占位值 0.0。取按标题对 SHA-256 哈希的 **1/50 确定性采样**（`_SAME_SRC_ANCHOR_SAMPLE`；1 = 全量、0 = 不采该规则）：同一标题对恒定入选或恒定跳过，样本集可复现；其余规则全量采集。

在该基线上的实测：94,706 → 37,913 行（40%），`same_src` 保留 1,106 条，仍高于校准工具的样本建议（同源 ≥50 条）。

### 2.2 保留期 30 天 + 写入时刻双判据

- `_ANCHOR_RETENTION_DAYS = 30`（`INVEST_DEDUP_ANCHOR_RETENTION_DAYS` 可覆盖，0 = 不按时间裁剪）。依据：30 天窗口在该基线上保留 68% 行，校准样本量仍充足；120 天窗口等于不裁。
- 保留判定为 **`ts`（新闻发布时间）或 `written_at`（写入时刻）任一在窗口内即保留**。理由：补录/回溯抓取的新闻 `ts` 很老但刚写入，只按 `ts` 判定会让这类样本在写入后的第一次压缩即被裁掉。

### 2.3 体积目标 + 分支配额 + 并发让路

- **两个常量分工**：告警线 `_ANCHOR_SIZE_WARN_BYTES`（32 MB，只提示）与裁剪目标 `_ANCHOR_SIZE_TARGET_BYTES`（**24 MB**，触发裁剪）。8 MB 缓冲用于避免每次运行都越线。
- **裁剪顺序**：保留期裁完仍超目标时，按时间从最旧继续丢到 ≤24 MB。
- **分支配额**：每分支保留最新 `_ANCHOR_BRANCH_MIN_KEEP = 50` 条不参与裁剪。`cross_opposite` 仅 58 条、`cross_merge_bg2` 仅 300 条，配额确保稀有分支不会被整类裁光（被裁光会让校准报告呈现「该规则零命中」）。
- **并发写入让路**：读取前后比对 `(size, mtime_ns)`，期间被并发追加则返回 `aborted=concurrent-write` 且不写盘。压缩是「读全文 → 替换」，不得吞掉另一进程刚写入的行。
- **按需重写**：无行可裁且无需补标注时不写盘，避免几十 MB 空转。

### 2.4 规则时代标注

压缩时给缺 `anchor_rules_version` 的行补 `ANCHOR_LEGACY_ERA = "legacy"` 标注并计数；校准报告把样本分「当前指纹 / 历史指纹 / 未标注」三桶，并列出历史指纹 Top3。

选择标注而非删除：历史样本保持可回溯，同时与在用指纹的样本分桶统计，避免规则漂移对比失真。

### 2.5 按月 gzip 分片

写入 `data/calibration/dedup_anchors-YYYYMM.jsonl.gz`：

- **写**：`gzip.open(..., "at")` 追加新的压缩 member，不重写既有压缩块——写盘成本只与本次新增条数相关（性质见 `technical.md`），与文件体积无关。
- **读**：`read_anchor_lines()` 统一读取各月分片与旧版单文件；单分片损坏/截断时保留已读行并告警，不影响其它分片（校验样本宁可少几行，也不能让整份历史不可读）。
- **压缩**：读全部分片 → 三重条件裁剪 → 按记录月份重新分片 → 清理整月被裁空的分片；`KEEP_BACKUP=1` 时「整月删空」这条路径同样先留 `.bak`（否则该路径没有回滚点）。
- **兼容**：未压缩的旧格式单文件在首次压缩时并入分片并移除。

### 2.6 与「仅删除」方案的取舍

删除能立即降体积，但会丢历史样本，且在该基线上压不到阈值以下（键全唯一）。gzip 在同一份数据上给出约 **12 倍**压缩比，且逐月可独立重写、互不影响。分片 + 保留期 + 体积目标三者取交集，体积才有确定性上限。

## 5. 风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| 30 天窗口让校准样本不足 | 实测保留 68% 行；采样只作用于同源分支 | `INVEST_DEDUP_ANCHOR_RETENTION_DAYS=0` |
| 体积裁剪把稀有分支删光 | 每分支保留最新 50 条 | `_ANCHOR_BRANCH_MIN_KEEP` 调大 |
| 压缩吞掉并发写入的锚点 | 读取前后 `(size, mtime)` 比对，变化即放弃写盘 | 无需回滚（本次不写盘） |
| 裁错无回滚点 | `.bak` 校验后清理；整月删空路径同样留备份 | `INVEST_DEDUP_KEEP_BACKUP=1` |
| 分片损坏导致历史不可读 | 逐分片读取，坏分片只跳过其余内容 | 删除坏分片 |
| 采集影响报告耗时 | 写侧只追加当月分片、不读旧文件 | `INVEST_DEDUP_COLLECT_ANCHORS=0` |
