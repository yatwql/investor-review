## 1. 范围与非目标

**本次范围**：五条模式路径全改（A/B/C/D/E，见 §5.8 矩阵）——标准、标准+条件推理、正反辩论、辩论+条件推理、辩论失败回退，任一路径都受预算约束。

**收益定位**：本设计的**主收益是尾部时延与超时余量**（p90 由 85.5s 降到约 43s、最长 102.6s 压到约 45s），p50 只是附带改善（64.5s → 约 37s，占整份报告 p50 的 −27s / −20%）。不承诺数量级提升；成本节省（约 ¥2.0/月）不足以构成立项理由，只作副作用记录。

**范围**：降低「一次完整报告」的墙钟时延，主攻 LLM 关键路径上的 `expert_review`（智囊团深度复盘）与次关键 `health_check`（持仓体检报告）——手段是**同一模块内的表达预算**（分节篇幅上界 + 去重禁令），不改变模块参与集合、不改变分析维度、不改变报告结构。

**非目标**（明确排除，防止范围蔓延）：

- **不动 thinking 默认值**：`thinking_enabled_*` / `thinking_budget_*` / `reasoning_effort_*` 出厂默认保持现状（`expert_review` = 开、24000、medium）。降低思考强度只作为**用户可选参数**（阶段 4 只补实测数据与文档建议），不作为默认优化手段。
- **不做按专家的并行拆分**（见 §4 方案 B，拒绝理由已记录）。
- **不合并模块调用**（见 §4 方案 C，拒绝）。
- **不改报告章节结构与可见性**（章节顺序与可见性由 `src/python/core/registry.py` 注册表驱动，对应架构约束「报告序号与显示名不可硬编码」）。
- **不改缓存 TTL**（`llm_expert_review` / `llm_health_check` 均 14400s，见 `src/python/core/data_registry.py`）；「提高 TTL 换命中率」属产品决策，另案。
- **不动数据获取层**：2026-10-26 21:42 运行的 167.7s 中，~40s 数据准备开销由 `rf-924`（cninfo orgId 端到端墙钟 + 负缓存）处理，与本设计正交。

## 2. 实测事实与归因

### 2.1 时延构成（2026-10-26 21:42 运行 vs 同日 15:08 运行 vs 生成样本统计）

| 阶段 | 2026-10-26 21:42 | 2026-10-26 15:08 | 生成样本统计（n） |
|---|---|---|---|
| 总耗时 | 167.7s | 121.1s | — |
| 数据准备 | 52.7s（含 cninfo 挂起 40.2s，由 `rf-924` 单独处理） | 6.5s | — |
| LLM+新闻 | **108.6s** | 94.4s | — |
| ├ 智囊团深度复盘 | **82.6s** | 70.6s | 40 个生成样本：均值 65.3s / p50 64.5s / p90 85.5s / max 102.6s |
| ├ 持仓体检报告 | 43.8s | 28.0s | 39 个生成样本：均值 30.7s / p90 43.8s / max 49.3s |
| ├ 穿透深度分析 | 10.8s | 11.3s | 38 个生成样本：均值 9.5s / max 15.0s |
| └ 全球政经局势 | 5.5s | 5.0s | 37 个生成样本：均值 4.6s / max 6.1s |
| HTML 生成 | 4.2s | 18.3s | — |

`智囊团` 在 40 个生成轮里**恒为关键路径**（逐轮比对：一次也不是其他模块最长；均值 65.3s，恒大于并行发生的 `体检`），因此它是唯一值得动的目标。

> **统计口径**：取 `breakdown["LLM+新闻"][模块名]` 的非零样本，且剔除该模块 `cached=True` 的会话（`智囊团` 43 轮中 3 轮命中缓存 → 40 个生成样本；`体检` 39 / `穿透` 38 / `政经` 37 个生成样本）。

### 2.2 时延归因模型（可复算）

模块墙钟 ≈ 输出 token 数 ÷ 模型输出速率（+ 固定开销，实测可忽略）：

| 模块（2026-10-26 21:42 单轮样本） | 输出 tokens | 墙钟 | 折算速率 | thinking |
|---|---|---|---|---|
| 智囊团 | 13,272 | 82.6s | 161 tok/s | 是 |
| 持仓体检 | 6,836 | 43.8s | 156 tok/s | 是 |
| 穿透深度 | 1,761 | 10.8s | 163 tok/s | 否 |
| 全球政经 | 603 | 5.5s | 110 tok/s | 否 |

逐轮复算的折算速率落在 **159–210 tok/s**（p10 159 / 中位约 190），另有 3 轮出现 306–442 tok/s 的异常值（疑似重试或计数口径，不计入口径）；按输出分箱的墙钟均值为 9k→59s、12k→70s、15k→90s，单调上升，且拟合残差显示存在 **10–15s 固定开销**（排队 + 首 token + 思考前置）。因此时延模型取：

```text
t ≈ 12s + out_tokens / 190
```

时延由输出长度**主导**（不是纯正比）——这是「预算能省多少」的估算基准，也是 §9 验收目标的算法来源。

**结论**：省时延 = 省输出长度。按中文 ≈1.2 token/字估算，现输出 12,546 tokens ≈ 1.05 万字；把 `expert_review` 压到 4,000~4,800 字（≈4,800~5,800 tokens），墙钟从 ~65s（均值）降到 ~30–36s，单轮总时延降 30–45s（叠加 `rf-924` 的 ~40s 数据准备收益，报告总时延 p50 从 134.5s 降到 ~105–110s、p90 从 170.3s 降到 ~125–130s）。

### 2.3 统计前提与局限（结论的适用边界）

| 前提 | 实测 | 对结论的影响 |
|---|---|---|
| 单模型单线路 | 43 轮 `expert_review` 全部为 `deepseek-v4-flash`（provider `deepseek-main` 40 轮） | 折算速率可比；换模型/换线路需重测（速率与 max_tokens 行为都可能变） |
| thinking 全开 | 43 轮 `thinking=True`，**没有同模块 thinking 关闭的对照样本** | 「时延由输出长度主导」是同模型下的**观察证据**，思考占比无法在现有数据里完全分离；阶段 1 补一次 thinking 关闭对照采样即可闭环 |
| 缓存命中会话 | 43 轮中 3 轮该模块 `cached=True` | 统计以 40 个生成样本为准，避免把命中轮当成生成轮 |
| 与阶段总时长的一致性 | 四模块子项之和恒大于「LLM+新闻」阶段时长 | 四模块并行（thinking 并发上限 2，`expert_review` 与 `health_check` 同时跑） |
| 持仓规模 | 40 个生成轮 `holdings_count` **恒为 12**（单组合样本） | 「输出长度」结论限于该规模；换组合需复核（持仓数会改变输入与铺陈量） |
| 超时边界 | 实测最长 102.6s（16,884 tokens）；按 p10 速率 159 tok/s 外推，24k 输出约 151s，会越过 `timeout_expert_review=120` | 目前**未实测触及**超时，属**尾部外推风险**：预算把这条尾部削掉 |
| 成本口径 | 9 轮有币种快照（含 3 轮部分模块运行）拟合 `cost ≈ ¥4.29/M 输出 + ¥1.32/M 输入`；完整运行（≥5 次调用）6 轮均值 ¥0.136，1 轮高峰价偏离拟合 | 成本降幅按「输出 token 占比」表述，与峰谷价无关；基准取完整运行均值 |

### 2.4 输出长度为什么失控（根因）

`llm/prompts_core.py:60 _SYSTEM_EXPERT_REVIEW` 规定「三阶段 / 5 位专家 / 两轮辩论」，但**全篇没有任何篇幅上界**：

- 对照：`_SYSTEM_GLOBAL_MACRO`（`src/python/llm/prompts_core.py:57`）写了「500字内」，其输出稳定在 603 tokens；
- `_SYSTEM_HEALTH_CHECK`（`src/python/llm/prompts_core.py:85`）给出五维骨架但无字数，输出 6,836 tokens；
- `expert_review` 无字数 → 模型按「尽量完整」铺开，40 个生成样本落在 8,756–23,888 tokens（均值 12,546）。

现有唯一的上界旋钮是 `output_brief_{module}`（`src/python/llm/skeleton.py:566`）：打开后仅在 system prompt 尾部追加「精简模式，输出 N 字以内」，`expert_review` 的 `N=300`（`src/python/llm/generators_singletons.py:214`）。**出厂默认关闭**，且 300 字对「5 专家 × 2 轮 + 定音锤」是不可执行的粗档（会砍掉交付物主体），所以它不是可行解，但证明了机制面已经存在。

## 4. 候选方案与取舍

### 方案 A（选定）：表达预算 —— 分节篇幅上界 + 去重禁令

在 system prompt 内为每个阶段/每轮辩论/每个输出块给出字数或条数上界，并禁止复述输入数据。

- 收益：直接作用于唯一瓶颈（输出 token），预计 −45~55s；成本同步下降（实测单次 `expert_review` ¥0.059，按输出折半估 ¥0.03 量级）。
- 风险：内容密度下降（可读性/决策价值），需质量守门（§5.7）。
- 技术债：低——不新增配置面、不改调用链、不改缓存族，只改提示词常量与非默认档措辞。

### 方案 B（拒绝，保留观察）：按专家拆分为多次并行调用

把 5 位专家拆成 5 次小调用并行，再跑一次「指挥官融合」。

拒绝理由：

1. **并行度已被信号量卡死**：thinking 模块并发上限 2（`llm_max_thinking_concurrency`），5 个 thinking 子调用 + 体检会排队，关键路径 = 排队后的串行和，不降反升。
2. **输入 token ×N**：每个子调用都要带完整持仓上下文（本模块输入已 5,786 tokens），成本与耗时同时放大。
3. **缓存族与指纹矩阵扩张**：新增 5 个键族 + 5 组指纹（受「指纹与缓存键唯一事实来源」约束），预检/写侧成对维护，后期漂移风险高。
4. **跨段一致性无解**：辩论的价值在「互相反驳」，拆开并行后第二轮失去上下文。

### 方案 C（拒绝，保留观察）：智囊团与持仓体检合并为一次调用

拒绝理由：两者用途（决策 vs 评分）、TTL、开关粒度、失败语义都不同；合并后任一处参数/提示词变更会**双双失效**（缓存爆炸），且合并输出更长，时延未必降。与「一次生成一个模块」的既有模块注册模型（「LLM 模块注册」约束）冲突。

### 方案 D（选定为可选参数，不设默认）：思考强度参数化指引

`thinking_budget_*` / `reasoning_effort_*` 已是配置项，阶段 4 只补「降低 effort 的实测差异」与手册建议（用户嫌慢可自行降档），默认不动。依据 §2.2：当前思考不是主要瓶颈，降思考的边际收益低于压输出，且会动质量，故不设为默认。

## 5. 选定方案详细设计

### 5.1 表达预算表（待校准档位）

预算作用于**输出表达**，不删分析维度：5 位专家、两轮辩论、量化调仓方案、风险提示全部保留。

| 输出块 | 现实测 | 预算（待校准） | 依据 |
|---|---|---|---|
| Phase 1 召集令（核心矛盾 + 5 位专家立场） | 不可分 | ≤ 600 字 | 每人一行立场 + 一句核心矛盾 |
| Phase 2 第一轮（方向立论） | 不可分 | 每位专家 ≤ 200 字（5 人共 1,000） | 主张 + 一条数据引用 + 一个判断 |
| Phase 2 第二轮（互相反驳、聚焦调仓优先级） | 不可分 | 每位专家 ≤ 200 字（5 人共 1,000） | 只写「被谁反驳 / 修正为什么」，不复述第一轮 |
| Phase 3 定音锤（量化调仓方案 + 风险提示） | 不可分 | ≤ 1,200 字 | 方案 + 优先级 + 风险各一段 |
| `### 操作建议` 表 | 不可分 | ≤ 8 行（≈ 200 字） | 现有表结构不变（解析侧依赖） |
| **合计预算** | 12,546 tokens（≈ 1.05 万字） | **≈ 4,000 字（余量上限 4,800 字，≈ 4,800~5,800 tokens）** | 按 `t ≈ 12s + out/190` → 37~42s（区间 32~46s） |

> **换算口径**：中文 ≈1.2 token/字（下行估算同）。实测输出 12,546 tokens ≈ 1.05 万字，与「三阶段五专家两轮」的铺陈体量吻合。
> **预算校准方法**（阶段 2 执行）：以「结构完整 + 抽检通过」为约束，从 6,000 字向下二分（6,000 → 4,800 → 4,000 → 3,200），每档同数据同模型跑 3 次取 p50，取「质量守门不劣化」的最小档作为最终默认。
>
> **字数的适用边界**：字数约束对散文段落可靠，对 Markdown 表格会失真（表格每字符 token 略高于散文），故表格类输出（`### 操作建议`、量化指标）用**行数/条数**约束，不按字数。

### 5.2 提示词改法（三类改动）

1. **分节预算**：在每个 Phase / 每轮辩论 / 每个输出块前标注字数上界（如上表），并在末尾给一句总预算复述（「全篇 ≤ N 字，超出部分将被截断」）。
2. **去重禁令**（省 token 的最大来源）：明确「不得复述输入段落中的数值表格、不得重复已在上一轮说过的论点、不得把同一结论换句再说」。当前输出里大量篇幅是复述持仓明细与指标表。
3. **表达格式**：专家发言用「**专家名（立场）**：结论句 → 关键数据 → 判断」单段式，禁止每人多段铺陈；表格优先于长句（`### 操作建议` 保持现有表头，解析契约不变）。
4. **结构先行（离线实测）**：6 次受预算约束的生成中，模型 **6/6 整段丢掉了「操作建议」表**——被裁掉的正是结构化交付物。故预算文案必须把表格要求写成硬性结构指令（「必须在末尾输出 `### 操作建议` 表格，表头不变，缺表即不合格」），且门禁把「表存在」单列为硬性项（要素机检看不出缺表）。

### 5.3 与既有「精简模式」的关系（单源化）

现状会出现两条长度指令叠加（system prompt 的预算 + `output_brief` 的「300 字以内」），语义冲突。阶段 3 一并收敛：

- `output_brief_{module}=true` 时追加的文案统一为「在既有分节预算内进一步压缩：全篇 ≤ 预算的 60%，保留全部小节标题与结论」——只有这一处长度指令；
- `output_brief_limit` 的语义定义为「压缩强度来源」，不参与「全篇字数」表达（全篇上界一律由分节预算合计给出）；
- 该改动落在 `src/python/llm/skeleton.py:566` 一处 + 各模块传参不变，避免「两套长度口径」。

### 5.4 与报告深度档位的关系（正交）

`depth_profile` 管**参与集合**与新闻采集量（三档：`brief` 仅 `global_macro`；`standard` 按模块开关全参与、新闻按用户配置；`deep` 全参与且新闻不少于 500 条，见 `src/python/llm/depth_profile.py` 与 `src/python/core/constants.py` 的 `REPORT_DEPTH_LEVELS`），本设计管**单模块篇幅**。二者不交叉：档位选 `brief` 时本预算不适用（该模块不参与）；`standard`/`deep` 下预算均生效。文档需写明这层关系，避免用户以为「调档位 = 调节篇幅」。

### 5.5 指纹与缓存影响（关键架构判断）

| 变更形态 | 是否进指纹 | 理由 |
|---|---|---|
| 改 system prompt **常量**（`_SYSTEM_EXPERT_REVIEW` 等） | **否**（现有机制） | `generation_params_suffix()` 只在 `system_prompt_{module}` 有覆盖时追加 `sp=` 后缀；常量不在指纹内 |
| 改 `output_brief_{module}` 开关 | 是（`ob=1`） | 既有 `generation_params_suffix()` 已覆盖 |
| 若将来把预算做成**配置项** | **必须并入** | 否则「改预算 → 键不变 → 未压缩的长文继续命中」；口径与 `llm/depth_profile.py` 一致（档位不写提示词正文，写入就必须并入指纹） |

对「常量变更不进指纹」的取舍：**接受**。理由——预算只改变「表达长度」，不改变内容事实；存量缓存（TTL 4h）在同一天内继续供应未压缩的长文属可接受，且 4h 后自然切换。副作用是**A/B 测量必须强制生成**（`force_llm` / `force_modules`），不得依赖缓存自然过期。此点必须写进阶段 2 的执行说明，否则会得到「没有变化」的假结论。

> **落点已定案：取「系统提示常量」形态**。不取「写入用户提示词」的理由：后者会让全体用户缓存一次性失效（约 ¥0.13 一次 + 一次全量重生成），且此后每次调预算都再失效一次，代价与收益不匹配。副作用（存量 4h 缓存内仍返回长文）由「A/B 测量强制生成」吸收。

### 5.6 A/B 度量 harness

新增离线评测脚本 `scripts/eval-llm-budget.py`（按 `scripts-reference.md`「命名约定」取 `eval-` 前缀，仅本机手工运行，**不进三档门禁**）：

- 输入：冻结的持仓快照 + 固定指标上下文（避免每轮数据漂移）；
- 动作：以「提示词预算版本」为自变量，强制生成（忽略缓存），每版本跑 3 次；
- 输出：JSON + Markdown 表（`docs/tmp/llm-budget/`），字段 = 输出 tokens / 墙钟 / **按 Phase 分段的字数** / 结构完整布尔 / `fact_fix_total`（分段字数按提示词的 Phase 标题切分，否则分节预算无法校准，只能测总量）；
- 复用：直接调用 `generate_expert_review(..., force=True)`，不复制调用链。

### 5.7 质量守门指标（分三层：可机检硬门禁 / 离线评测 / 真机观察）

| 指标 | 阈值 | 判定来源 | 适用层 |
|---|---|---|---|
| 结构完整率 | 100% | 复用既有解析：`core/decision_header.parse_structured_header`（三字段严格口径）+ `report/decision_llm_capture` 的操作建议表行解析（≥1 行）；**注**：`expert_review` 不在 `report/llm_quality._REQUIRED_MARKERS`（标准/辩论两模式章节不同，硬编标记会误判），故结构判定由上述两个解析器组合，不新建第三套解析 | 机检（硬门禁） |
| 数值事实修正数 `fact_fix_total` | ≤ 基线 p75（当前中位 5） | `perf.counters`（`src/python/llm/fact_checker/_corrections.py` 写入） | 真机（perf） |
| 代码级事实修正 `fact_fix_code` | 不高于基线 | 同上（比“幻觉过滤命中数”可靠：后者只在内存里计数、不入 perf） | 真机（perf） |
| 质量评级不降级 | `grade_module` 评级不劣于基线 | `src/python/report/llm_quality.py::grade_module` | 真机 |
| 人工抽检 | 3/3 通过（12 项 checklist：每专家立场、两轮反驳、量化调仓、风险提示、代码引用、无「本日盈亏」误述、无虚构持仓、无复述整表） | 抽检记录入 `docs/tmp/llm-budget/` | 人工（阶段 2/3） |
| 输出字数 | 落在预算 ±20% | eval 与 `perf` 的 `output_tokens` | 离线+真机 |
| 操作建议表存在 | 标准模式必须 ≥1 行（离线实测缺失率 100%） | 同一表行解析（Markdown 竖线表 / HTML `<tr>`） | 机检（硬门禁） |
| 建议条数 / 覆盖品种数 | 不低于同输入基线 | 既有 `src/python/report/decision_llm_capture.py` 表行解析（条数、code 集合） | 离线+真机 |
| 结论集差分 | 新品种/指标/建议集合覆盖基线 ≥90%，关键持仓品种不得缺失 | 同数据新旧两版各 3 次，按集合比对 | 离线（阶段 2） |
| 补写触发率 | ≤30%（超过说明预算与要素要求不匹配，应放宽预算） | eval 产物 `rewrite_triggered` 计数 | 离线+真机 |
| 补写未修复率 | ≤5%（补写后仍缺项的比例；这部分原样产出并记 WARNING） | 补写接缝日志计数 | 真机 |

**深度保障的落地形态（已锁定为「机检 + 差分 + 失败自动补写」）**：

1. **机检要素**（生成后、写缓存前，零新增调用）：解析每专家发言的四要素（立场 / 数据依据 / 结论 / 反驳对象）与 Phase 3 的四要素（方案 / 优先级 / 风险 / 置信度）；缺项即标记。
2. **结论集差分**（离线评测阶段，不进驻生产路径）：同输入新旧两版各 3 次，比对品种集合、指标名集合、`(品种, 方向)` 建议集合。
3. **失败自动补写**（唯一进入生产链的新逻辑；**离线已验证有效**：缺表时一次短调用 +2.0~2.4s、约 290~330 输出 tokens，补出 8 行表并覆盖 8~10 个品种，结构判定转绿）：机检缺项时追加一次**短调用**——输入只给「缺失要素清单 + 原输出相关片段」，要求补齐缺失要素并返回片段；合并进原输出后再次机检，仍不齐则放弃补写、按原样产出并记 WARNING。
   - 触发条件严格限于「机检缺项」，不因字数/风格触发；
   - 单次补写输入 ≤1,500 tokens，成本量级 ¥0.01/次；
   - 补写失败/超时一律降级为原输出，不阻断报告生成；
   - 需要一个可关闭的接缝开关（缺省开启），便于线上快速回退。

### 5.8 模式组合矩阵（辩论 × 条件推理）

智囊团有两个独立开关（`src/python/config/features.py` 分析增强组）：`llm_debate_procon`（正反辩论）与 `llm_debate_conditional`（条件推理）。**条件推理并非辩论专属**：`llm/module_fingerprint.py::debate_feature_cache_suffix` 的注释与 `generate_expert_review` 的 `enable_conditional` 参数都表明，非辩论模式下它同样改写提示词（追加情景分析指令），因此矩阵是 2×2 五条路径，而不是「辩论开/关」两种。

| 组合 | 开关 | 实际调用 | 生效的系统提示 | 缓存族 / TTL | 预算落点 |
|---|---|---|---|---|---|
| **A 标准** | 无 | 1 次 `generate_expert_review` | `_SYSTEM_EXPERT_REVIEW` | `llm_expert_review_*` / 14400s | 分节预算全部生效（§5.1） |
| **B 标准 + 条件推理** | conditional | 1 次（同上） | 同上 + 条件推理情景指令（user prompt 追加，`src/python/llm/prompts_action.py:305-325`） | 同上，指纹带 `_c` 后缀 | 分节预算 + 多情景段（情景取自 `debate.conditional.scenarios`，默认 3 个：上涨/下跌/震荡；每个≥2 句行动建议，≤120 字/情景），情景段**不可删** |
| **C 正反辩论** | procon | 3 次：pro → con → synthesis | `_SYSTEM_DEBATE_PRO` / `_SYSTEM_DEBATE_CON` / `_SYSTEM_DEBATE_SYNTHESIS` | `llm_debate_pro_*` / `_con_*` / `_synthesis_*` / 86400s | pro/con 各 ≤1,200 字（`skip_scenarios=True`，不写情景）；synthesis ≤1,500 字（禁复述白/黑脸） |
| **D 辩论 + 条件推理** | both | 3 次（同上） | PRO / CON + `_SYSTEM_DEBATE_SYNTHESIS_CONDITIONAL` + 集中度问答附段 | 同上，指纹带 `_c` | pro/con 各含配置情景（默认 3 个）× ≤120 字；synthesis 按情景分别给建议，≤1,800 字 |

**情景段有两种形态，两者都不可删**（`src/python/llm/prompts_action.py:305-340`）：

- `enable_conditional=False` → **标准情景 fallback**：要求输出「### 情景分析」，含上涨/下跌 20% 两段，每段给方向判断与具体品种建议；
- `enable_conditional=True` → **条件推理情景**：按场景清单逐条给「至少 2 句具体行动建议」；
- 两者互斥（不在同一份提示词中重复出现），因此预算只需按当前形态给字数，**但不得把情景段整个省掉**；
- **边界子情形**：`debate.conditional.scenarios` 为空列表时，条件推理分支不追加任何情景段，且因为 `enable_conditional=True` 也不会回落到标准两情景（`src/python/llm/prompts_action.py:326` 的 `not _scenario_appended and not enable_conditional` 条件）——此时输出**没有情景段**。预算与验收都按配置判定：有配置则情景段必须齐全，无配置则不要求，不能一律断言「情景段存在」。

**组合 E（辩论开启但失败回退）**：`pro` 或 `con` 生成失败、或抛异常时，`src/python/llm/_llm_dispatch.py` 回退调用 `_original_expert`（标准路径）。此时：

| 项 | 实际行为 |
|---|---|
| 提示词 | 标准 `_SYSTEM_EXPERT_REVIEW`（**非**辩论三套），条件推理开关仍生效 → 等价于 B 组合 |
| 缓存族 | `llm_expert_review_*`（带 `_c` 后缀），不是 `llm_debate_*` |
| 报告标签 | `debate_info` 被置 `None` → 展示为普通模式；若 pro/con 成功但综合失败，走 pro+con 拼接并标「辩论模式」，属另一种中间态 |
| 预算影响 | 辩论路径与回退路径的提示词须同批修改；只覆盖其一时，「开关打开但回退」仍不受预算约束 |

**七条设计约束**（由矩阵直接推出）：

1. **预算必须逐条 system prompt 各一套**：只改 `_SYSTEM_EXPERT_REVIEW` 时 B/C/D 三个组合不受预算约束，预算对四分之三的用法无效。阶段 3 的改动面是 **5 个系统提示常量**（`_SYSTEM_EXPERT_REVIEW` / `_SYSTEM_DEBATE_PRO` / `_SYSTEM_DEBATE_CON` / `_SYSTEM_DEBATE_SYNTHESIS` / `_SYSTEM_DEBATE_SYNTHESIS_CONDITIONAL`）+ **1 个辩论附段**（`_SYSTEM_DEBATE_SYNTHESIS_QA_APPENDIX`，集中度问答）+ 1 个条件推理情景指令段；`_SYSTEM_HEALTH_CHECK` 另计（次关键模块）。
2. **情景分析是内容契约，不是可压缩项**：B/D 的情景段按 `debate.conditional.scenarios` 配置生成（默认 3 个），预算是「压表达」而非「删段落」——预算表显式保留情景段并单独给字数；无配置时该段本就不存在，验收按配置断言。
3. **时延收益不能按单次调用线性外推**：C/D 是 3 次调用，且 synthesis 的输入 = 白脸 + 黑脸全文，pro/con 变短会连带缩短 synthesis 输入（利好），但若压得过紧导致论据不足，synthesis 质量问题会被放大。因此辩论组合按单篇完整性设下限（pro/con 各 1,200 字、综合 1,500 字），且**不以时延为收益**——三次调用的总输出与标准模式相当甚至更多，预算在那里只防失控（辩论是实验项，默认关闭）。
4. **集中度问答段只属辩论路径**：`include_concentration_qa=True` 仅辩论调用传入（标准路径为 False），预算与它在标准模式无关；辩论路径须保留该段（阈值触发，非开关）。
5. **组合标识要与实物一致**：`src/python/report/_debate_utils.py` 的「情景推理模式 / 辩论模式」标签来自 `debate_info`。回退（组合 E）时标签为空、内容为标准提示词产出——验收时按「标签 ↔ 实际提示词路径」一致性检查，避免标称辩论却跑标准口径。
6. **成本预估的分支**：`src/python/llm/cost_forecast.py::is_feature_enabled_for_debate()` 只读 `llm_debate_procon`；B 组合按单模块计，辩论三键在 `_DEBATE_KEYS` 里合并计入 `expert_review`。预算改变单篇输出后，预估与实际会短暂偏离——阶段 3 只对齐口径、不改算法。
7. **缓存与指纹已能隔离组合**：条件推理经 `debate_feature_cache_suffix()` 以 `_c` 进入 `expert_review` 指纹，辩论三族走各自的写侧指纹，开关切换不会串缓存；但系统提示**常量**变更仍不进指纹（§5.5 的取舍在五路径下不变），所以测量必须强制生成。

**度量与验收按组合分层**（避免 5 路径 × 4 档 × 3 次的组合爆炸）：

| 组合 | 阶段 2 测量 | 验收要求 |
|---|---|---|
| A 标准 | 4 档预算 × 3 次（主战场） | 质量守门全绿 + p50 墙钟 ≤42s |
| B 标准+条件 | 选定档 × 2 次 | 结构完整 + 情景段与配置一致（配置非空则齐全）+ `fact_fix_total` 不升 |
| C 正反辩论 | 选定档（按辩论预算）× 2 次 | 三段结构完整（白/黑/综合）+ 3 次调用总墙钟不升 |
| D 辩论+条件 | 选定档 × 2 次 | 同上 + 情景段与配置一致 + 综合段按情景给建议 |
| **E 辩论失败回退** | 注入 pro/con 失败（mock 一处失败）× 2 次；需新增 1 例失败注入用例作为测量载体（现有测试无该路径） | 回退路径走标准提示词且带预算（无长文残留）+ 标签与实物一致 |

`scripts/eval-llm-budget.py` 因此需要一个 `--mode` 参数（`standard` / `standard-conditional` / `debate` / `debate-conditional`），通过 features 覆写切换组合，并在产物里记录组合标识——否则测得的结果无法归属到某一组合。

### 8.1 收益量化（全部来自同一份 40 个生成样本）

> 下表收益对应**标准模式（A/B 组合，单次调用）**；辩论组合（C/D）是三次调用、总输出与标准相当，收益仅体现为「防止单篇失控」，不计入时延收益。

| 收益项 | 现状 | 预算后（按 `t ≈ 12s + out/190`） | 幅度 |
|---|---|---|---|
| 智囊团 p50 | 64.5s | 约 37s | −27s（−42%） |
| 智囊团 **p90** | **85.5s** | **约 42.5s** | **−43s（−50%）** |
| 智囊团 最长 | 102.6s | 约 45s | −58s |
| 距 120s 超时的余量 | p90 后余 34.5s | 余 77.5s | 翻倍 |
| 离线实测（4,000 字档，含补写） | 基线智囊团 p50 64.5s | 38.4~43.6s（生成 36~41s + 补写 2.0~2.4s） | −33%~−40% |
| 整份报告 p50 | 134.5s | 约 107s | −27s（−20%） |
| 整份报告 p90 | 170.3s | 约 127s | −43s（−25%） |
| 单轮 LLM 成本 | 均值 ¥0.136 | 约 ¥0.103 | −24%（按 2.07 轮/天折算月成本约 ¥8 → 省约 ¥2.0/月，**不构成收益理由**） |

**收益的诚实结论**：p50 只降 20%（2 分 14 秒 → 1 分 47 秒），不足以单独支撑改造；真正值钱的是**尾部**——「抽到最坏那次要等 1 分 43 秒」变成「最坏也就 45 秒」，以及超时余量翻倍（失败风险下降）。收益定位因此是「稳定性/尾部治理」，不是「提速一倍」。

### 8.2 收益-风险对照与决策规则

把风险按「是否阻断交付」重新分级，再与收益对照（缓解后的残余风险才是决策依据）：

| 风险 | 等级 | 缓解后的残余风险 | 判定 |
|---|---|---|---|
| 分析深度下降（用户可感知） | 中/高 | **中/中**——真实但可量化：`fact_fix_total` 与输出长度**无相关**（24 个样本 r = −0.06，长输出组平均修正 4.11 反而低于短输出组 5.20），说明「写得多 ≠ 错得多」，压缩不必然增加事实错误；剩余风险是论证密度 | 阻断类：阶段 2 抽检任一不通过即终止 |
| 模式组合覆盖不全（A/B/C/D） | 中/高 | 低——矩阵化改造 + 每组合结构断言 | 阻断类，由矩阵覆盖消除 |
| 结构被压坏（操作建议表/决策头） | 低/高 | 极低——解析器回归用例 + 预算显式保留 | 阻断类，可机检 |
| A/B 假结论（缓存不失效） | 高/中 | 低——强制生成 + `cached` 断言 | 阻断类，可机检 |
| 辩论组合压过紧被综合段放大 | 中/中 | 低——辩论单独更宽预算 + 只要求「不劣化」 | 监控类（辩论默认关） |
| 模型/线路漂移、成本口径波动 | 中/中 | 低——按「字数」表述预算，观察期复核 | 监控类，不阻断 |
| 长输出触超时（尾部外推） | 中/中 | 低——预算削尾，本身是收益 | 监控类 |

**决策规则（按残余风险定档）**：

1. **投入有界**：阶段 1+2 的沉没成本约为「一个 eval 脚本 + 12 次采样」，不含生产代码改动——终止代价极低。
2. **任一门禁即终止**：阶段 2 出现「结构不完整」「抽检任一项不通过」「`fact_fix_total` 上升超过基线 p75」中任一条，直接归档为「已评估未采纳」，不进入阶段 3。
3. **收益不足也终止**：若选定档 p50 降幅 <15% 或 p90 降幅 <30%，说明预算对输出长度的实际约束力不足（模型不服从字数），同样终止，不为了「已经做了设计」而硬上。
4. **不以成本为决策依据**：¥2/月 的节省在任何风险面前都不划算，避免用成本数字给方案加权。


## 9. 验收标准

- **时延（主指标是尾部）**：`expert_review` p50 ≤ 40s（基线 64.5s）**且 p90 ≤ 50s**（基线 85.5s）；报告总耗时 p50 ≤ 110s、**p90 ≤ 135s**（基线 134.5s / 170.3s，含 `rf-924` 的数据准备收益）。
- **成本（参考项，不作验收门槛）**：单轮 LLM 成本约降 24%（输出 −7,546 tokens × ¥4.29/M ≈ ¥0.032，基准取完整运行均值 ¥0.136）；折算约 ¥2.0/月，**不构成立项理由**，只记录副作用。
- **质量**：§5.7 全绿，抽检 3/3。
- **不劣化**：`fact_fix_total`、幻觉命中、自检异常数均不高于基线 p75。
- **深度保障**：首轮 + 补写后要素齐全率 100%，其中「补写后仍缺项」比例 ≤5%；结论集覆盖基线 ≥90%；补写触发率 ≤30%（三项阈值同为**约定值**，阶段 2 按实测校准后再锁定）。
- **组合覆盖**：A/B/C/D/E 五条路径下结构完整（B/D 情景段与配置一致，C/D 白/黑/综合三段齐全，E 回退时仍带预算且标签与实物一致），且各自不劣化。
- **可回滚**：revert 阶段 3 的单次提交即恢复原行为，无需改配置。

## 13. 评估结论（不采纳）与量化结果

> **结论**：**不采纳**。表达预算能省约 30% 时延，但需以「正文篇幅减半 + 结构补写接缝」为代价；绝对收益小（每次约 19.5s、每月约 ¥2.8），不足以承担交付完整性与维护复杂度。生产代码未做任何改动。

### 13.1 离线评测（`scripts/eval-llm-budget.py`，2026-10-26/27）

固定输入：12 只持仓的冻结样本；模型 `deepseek-v4-flash`；thinking 开；每次生成后按需补写（`--repair`）。

| 预算档 | 次数 | p50（含补写） | 输出 tokens | 实际字数 | 超预算 | 建议表行数 / 覆盖品种 | 补写触发 |
|---|---|---|---|---|---|---|---|
| 基线（历史 40 次） | 40 | 64.5s | 12,546 | ≈1.05 万 | — | 未统计 | — |
| 3200 字 | 2 | **33.0s（−49%）** | 4,636 | 5,136 | **+60%** | 7.0 / 7.5 | 2/2 |
| **4000 字** | 5 | **45.0s（−30%）** | 7,416（+补写 537） | 5,244 | +31% | 6.8 / 8.0 | 5/5 |
| 4800 字 | 2 | 57.1s（−11%） | 8,116 | 5,536 | +15% | 6.5 / 6.5 | 2/2 |

**结构发现**：纯提示词约束下 **8/8 次丢失「操作建议」表**（含“缺表即不合格”“篇幅不足先压正文”两种加固）；加补写接缝后 **9/9 有表**（6.5~7 行、覆盖 6.5~8 个品种），补写代价 **+2.0~6.5s / 300~1,200 输出 tokens**（约 ¥0.002/次）。

### 13.2 缓存 TTL 提升（不采纳）

|---|---|---|
| 4h（现状） | 96/190 = 51% | **16/190 = 8%** |
| 8h | 119/190 = 63% | 16（不变） |
| 24h | 147/190 = 77% | 16（不变） |

**判据**：理论值远超实际，说明 miss 主因是**输入指纹变化**（持仓/行情/指标/环比差异），不是 TTL 到期。调 TTL 的真实收益 ≈ 0~7 轮/190（≤4%），**不实施**。

### 13.3 指纹瘦身（不采纳）

以 176 份持仓快照 + 190 轮运行复算（持仓身份 = 代码/份额/成本；176 份快照仅 27 种身份）：

| 策略 | 命中 | 命中率 | 陈旧中位 | 陈旧最大 |
|---|---|---|---|---|
| 全量指纹（现状，4h） | 16 | 8% | — | — |
| 仅持仓身份（4h） | 68 | **36%** | 47 分 | 3.7 小时 |
| 持仓 + 数据日期（24h） | 115 | 61% | 6.3 小时 | 21.6 小时 |
| 盘中 1h + 收盘后按日 | 66 | 35% | 49 分 | 8 小时 |

**折算**：较现状多命中约 52 次/92 天（≈0.57 次/天）→ 每月省约 18 分钟等待、约 ¥0.9。代价是命中时报告内的行情数值最多旧 3.7 小时且无提示；且该做法**违反「指纹与缓存键唯一事实来源」约束**（进了提示词的内容必须进指纹），属契约变更而非性能优化。**不实施**；若将来做「叙事与数值分离」改造，可一并重估。

### 13.4 复核触发条件（什么情况下重开此案）

1. 白天高频重跑成为常态（≥5 次/天），等待时间成为实际痛点；
2. 换更快线路/模型后仍需进一步提速，且已验证质量可接受；
3. 「叙事与数值分离」改造启动（届时指纹瘦身与缓存契约相容）；
4. 模型开始稳定服从字数预算（多档实测实际字数进入 ±10%）。
