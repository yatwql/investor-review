# DESIGN-TUI.md — 投资复盘助手终端交互契约

> **适用对象**：`src/python/tui/` 下一切交互改动——提示语、键位、面板版式、反馈与空态文案。
> **定位**：TUI 侧**唯一判据**，与 [`DESIGN.md`](DESIGN.md)（Web/报告视觉契约）对称：一个守「看什么」，一个守「怎么按、按了会怎样」。
> **守卫**：`src/test/unit/ui/test_design_tui_doc.py`（骨架 / 键表 / 表格列 / 口径句 / 护栏 / 术语表 / 闸门白名单交叉校验） + `src/test/unit/ui/test_prompt_contract.py`（上屏提示成分、禁用词、闸门白名单机检）。
> **设计依据**：TUI 人机工程治理设计（HCI 原则对照、措施分批与验收载体）——该设计稿已随 v0.13.x 治理批次完成并归档，本契约为其定稿判据。

## Overview — 基调与哲学

TUI 的第一用户是**在手机上用 SSH 看持仓的人**，不是写代码的人。因此：

| # | 原则 | 判据 |
|---|---|---|
| P1 | **识别优于回忆** | 数字编号是第一入口；字母只作别名；任何键都必须能在屏幕上看到说明 |
| P2 | **一键一义** | 同一按键全局只有一个含义；冲突时改语义，不改文案去圆 |
| P3 | **屏幕自解释** | 不翻手册即可走完主路径；`?` 在任何面板都能问到帮助 |
| P4 | **专家快路不牺牲可发现性** | 直达键/键名/组合输入保留，但必须出现在页脚或 `?` 帮助里 |
| P5 | **可机检优先** | 每条纪律都要有守护载体，不靠口头纪律 |

## Keys — 键分工总表

| 键 | 唯一语义 | 禁止用法 |
|---|---|---|
| 数字 `1..N` | 选择项（**第一入口**，编号连续无断层） | 不得跳号；不得与字母混用表达同一动作 |
| 子项编号 `7.1` | 某章节下的生成选项（十进制子编号；父章节编号保持稳定） | 不占章节编号、不单列返回项；父项关闭时置灰并提示原因 |
| 回车 | 执行**本行提示标注的默认项** | 不得表达「取消」；不得作为"无标注的默认"（必须写明默认项是什么）；屏幕上不得写作英文 `Enter`（同键两名会让人以为是两个键） |
| `?` | 帮助：无参=本面板可用键一览；`?N`=第 N 项详情 | 不得仅个别面板支持 |
| `0` | 返回上一层（首页即退出） | 不得在部分面板改为「返回上上层的上一项」 |
| `Esc` | 取消当前提示 / 返回上一层 | 不得直接退出程序（退出走 `0` / `X`） |
| 字母 `A-Z` | 直达别名（专家快路） | 不得成为唯一入口；不得只存在于代码而不上屏 |
| `/` | 主菜单关键词筛选（标签子串 / 按键精确命中；空回车清除） | 不得隐藏编号与字母（筛选只缩小范围，不改键义） |
| `↑` `↓` `Enter` | 面板内移动选中 / 执行选中 | 分档只改版式不改语义（约束 C29） |

## Prompts — 提示三段式模板

```
  <动作指令>（如 3）· <默认项声明> · ? 看说明 · 0 返回:
```

| 成分 | 要求 | 反例 |
|---|---|---|
| 动作指令 | 动词 + **一个具体示例** | 「请输入编号」 |
| 默认项声明 | 回车会做什么，写明动作名 | 「回车=确定」 |
| 帮助入口 | `? 看说明`（或 `?3 查看说明` 形态） | 只字不提帮助 |
| 返回键 | `0 返回` | 裸提示 `缓存管理> ` |
| 折行 | 超宽走 `wrap_prompt` / `wrap_hanging`（窄屏基准 40 列） | 长提示硬折导致光标脱节 |
| 面板输出 | **所有**上屏行（提示语之外，含表格/统计/日志/盒线面板）在 40 列下不得超宽：盒线面板用 `switch_panel.render_titled_panel`（宽/中档画框、窄档无框截断），长文本用 `wrap_hanging`、单行用 `truncate_display` | 无条件 `render_panel`（宽度内容驱动，窄屏撑出 49~57 列被终端硬折成锯齿） |

**禁止形态**：裸提示（无返回键）、只列按键字母（`(A/D/R/0)`）、纯占位符描述（`? 编号 看说明`）。

## Defaults — 默认项与取消标注语法

| 场景 | 写法 | 禁止写法 |
|---|---|---|
| 回车执行默认 | `回车=用缓存生成`（写明动作名） | `回车=确定` |
| 需要取消 | 用 `0` / `Esc`；确需回车取消时写 `回车=取消` 且置于句首 | 括注里藏「直接回车取消」 |
| 二选一确认 | `(y/N)`——大写一侧为默认 | 大小写混用、无默认暗示 |
| 危险操作 | 默认项必须是**安全侧**（中止/不覆盖） | 默认写盘、默认覆盖 |

## Colors — 配色角色（一色一职责）

多色可以，但每个颜色只承担一个职责；取值与 `src/python/core/ansi_colors.py` 同源，**非 TTY / `NO_COLOR` 下全部退化为无色**——文本本身仍可读，语义不依赖颜色。

| 角色 | 取值 | 用在哪 | 不得用在 |
|---|---|---|---|
| 品牌 | 橙 + 粗体 | 首页应用名与版本号 | 正文与状态值 |
| 结构 | 蓝 + 粗体 | 分组标题（首页 `── 生成报告 ──`、`[C]` 四块、`[S]` 六组）、面板横幅 | 状态值与键位 |
| 焦点 | 青 | 当前选中标记（首页 `>`、面板行首游标） | 未选中行 |
| 状态 | 绿 / 黄 / 红 | 正常 / 需要注意（数据偏旧、备用源失败、LLM 未配置） / 错误 | 整段正文 |
| 弱化 | DIM | 分隔线、页脚图例、详情括注 | 关键操作说明 |

**先排版后上色**：折行与截断必须在着色前完成；结构色统一经 `src/python/tui/text_layout.py` 的 `style_heading` 产出——首页与 `[S]` 分组标题改色只动这一处，两处必然同步；其余角色色按上表就地包裹，不自造新色。

## Vocabulary — 术语对照表

| 内部词（禁止上屏） | 用户词（上屏） |
|---|---|
| 强刷 / force | 重新生成（会调用 AI，计费） |
| 走缓存 / cache hit | 用已有结果（免费，可能不是最新） |
| 降级 | 改用备用方案（结果可能略旧） |
| 分档 / tier / 窄档 / 宽档 | 不上屏（版面差异用户无需知道名称） |
| 游标 / cursor | 选中项 |
| 配置漂移 | 与出厂默认不一致 |
| 熔断 / 退避 | 暂时失败，稍后自动重试 |
| `Enter`（按键英文名） | 回车 |

**适用范围（写在表后，避免两种口径互相误伤）**：

| 场景 | 口径 |
|---|---|
| TUI 提示行 / 反馈行 / 状态标签（含页头状态行、LLM 状态面板） | 本表用户词（`备用源` / `自动重试: 正常·暂时失败`） |
| Web 工作台、CLI 终端的**状态表与决策屏** | 与 TUI 同词——端点状态经 `core.system_info.circuit_display` 唯一归一，预算确认统一说「用已有结果继续」，三渠道不得各自命名同一决策 |
| 报告 / Web 的**数据降级**呈现（源失败占位、降级明细） | 沿用 [`DESIGN.md` Data States](DESIGN.md)：此处的「降级」指数据质量，不是端点重试状态 |
| 日志、代码注释、FAQ / 机制文档 | 保留技术词（熔断、退避、强刷）——排障与检索需要精确术语；`[V]` 日志详情同此口径 |

## Feedback — 反馈与空态口径

| 场景 | 前缀 | 要求 |
|---|---|---|
| 进行中 | `[..]` | 具体动作 + 进度（「正在获取行情（3/12）」优于「处理中」） |
| 成功 | `[OK]` | 带可核对的量（数量/路径/金额） |
| 部分失败 | `[!]` | 哪部分失败 + 影响 + 怎么办 |
| 错误 | `[ERR]` | 原因 + 下一步动作（不得只给异常类名） |
| 空态 | `[!]` | 说清「为什么没有」+「怎么才会有」 |
| 面板按键反馈 | 无前缀单行 | 一次按键必有可观察结果（C29 两档同语义） |
| 页头状态行 | 无前缀 | 五项常驻（上次报告/缓存过期/新鲜度/备用源/LLM），LLM 段 = 状态点 + 多链链首线路名；顺序与 `[M]` 面板编号同一口径（`config/_llm_providers.order_providers_by_chain`），窄终端先弃「详情」指引、五个语义段不折行 |

### 按键闸门白名单（`按任意键返回菜单`）

闸门只在**长输出后**保留——输出会被随后的全屏重绘顶出可视区，需要用户先读完：

| 闸门位置 | 理由 |
|---|---|
| `handlers_log._cmd_view_logs` | 运行日志详情（最多 200 条） |
| `handlers_log._cmd_view_health_history` | 数据源健康历史（最近 10 次） |
| `handlers_log._cmd_run_doctor` | 系统自检结果（逐项 + 修复建议） |
| `handlers_cache._run_cache_update` | 缓存更新结果摘要（多行统计块） |

其余一律**不设闸门**：面板命令完成、错误提示、取消提示都直接回菜单。

**报告收尾例外（非「按任意键」形态）**：`tui_handlers.finish_report` 在错误摘要与耗时排行之后打印产物清单并问「是否打开报告目录与报告？」——提示用二选一确认 `(y/N)`，**单键读取**（`y`/`Y` = 打开；默认 N，其余任何键含 `n`/回车/`Esc`/未知键都按 N 处理）；`Esc` 只跳过并回菜单（不退出程序），`Ctrl+C` 沿用 TUI 约定退出程序；非 TTY（脚本/管道）只打印清单、不询问。它同时承担「长输出先读完再重绘」的停屏作用，故不再计为「按任意键」闸门。
守护：`test_prompt_contract.py::TestPressAnyKeyGateWhitelist`（新增闸门即失败）。

## Do's and Don'ts — 护栏（与机检同源）

1. **DO** 用数字编号做主入口 · **DON'T** 只给英文首字母（中文标签拿不到助记线索）
2. **DO** 让回车的含义来自提示行标注 · **DON'T** 让回车在不同提示处有时确认、有时取消
3. **DO** 每个面板都支持 `?` · **DON'T** 让帮助只存在于某一个面板
4. **DO** 上屏用用户词 · **DON'T** 把强刷/降级/游标这类内部词直接印给用户
5. **DO** 一次按键给可观察反馈 · **DON'T** 静默吞键（窄屏未登记键也要一行说明）
6. **DO** 长输出后保留「按任意键」 · **DON'T** 每个动作后都加闸门（主路径击键数被放大）
7. **DO** 提示超宽折行 · **DON'T** 假设终端有 100 列
8. **DO** 破坏性操作默认走安全侧 · **DON'T** 让默认项覆盖用户数据

## Iteration Guide — 增量指引

| 场景 | 必做 |
|---|---|
| 新增菜单项 | 编号连续（数字键为主入口）；同步两本手册的主菜单 code block（`check-doc-drift` 手册菜单块守护） |
| 新增面板 | 走 `panel_runtime.panel_loop`；提示套三段式模板；`?` 与 `0` 由运行时提供；补窄/宽两档用例 |
| 新增提示 | 默认项必须标注；超长走 `wrap_prompt`；上屏词查术语对照表 |
| 改键位 | 先改本文 Keys 表，再改实现与手册，最后跑菜单块与击键基线用例 |
| 改主菜单分组 | 改 `tui_menu.MENU_GROUPS` 后跑分组覆盖用例（覆盖全项一次、退出项在外）+ 双手册菜单块 |
| 改反馈文案 | 对照 Feedback 表选前缀；错误必须带下一步动作 |

## Known Gaps — 未覆盖面

| 缺口 | 现状 | 状态 |
|---|---|---|
| 提示模板化 | `panel_loop` 提示全部由 `panel_prompt` 产出（AST 机检）；`input_choice` 类确认屏为「问句行 + 键位行」两行式，受机检规则 3/6 约束（必须声明回车动作名），不强制套单行模板 | 完成 |
| `?` 帮助覆盖 | `?` 与 `?键` 由 `panel_runtime` 统一承接；单项详情经 `PanelItem.detail` 由各面板提供（`[C]/[A]/[I]/[M]`/缓存面板已填，`[S]` 走 `on_help` 富详情）——面板各写业务含义，渲染单源 | 完成 |
| 默认项标注一致性 | 机检三重：回车取消不得藏括注、屏上键名统一写「回车」（禁英文 `Enter`）、回车必须带动作名且取消类语义置于句首；报告链/追问链提示已逐条复核（默认项均写明动作名） | 完成 |
| 术语改写 | 上屏文案已去内部词；守卫 `test_prompt_contract.py::TestForbiddenVocabulary` | 完成 |
| 按键闸门 | 已收敛为 4 处「按任意键」长输出闸门（白名单在 Feedback 节）；报告收尾改为**单键 `(y/N)` 产物确认**（同样是「按一下才回菜单」，但键义明确、不多一步），短反馈不再等待 | 完成 |
| 击键数门禁 | 基线快照 6 条动线（含 `/` 筛选动线）；三条 E2E 动线另断言关键语义词上屏（P0 跑生成 1 条 / P2 跑 3 条） | 完成 |
| 主菜单任务分组 | 已按「生成报告 / 数据与查看 / 配置 / 诊断与排查」四组渲染，退出项单列；`/` 关键词筛选可用 | 完成 |
| 编号为主入口 | **已评估未采纳**：主菜单键位（字母 + `1/2/3`）已在三渠道文档与用户肌肉记忆中稳定，全量重编号为 `1..19` 会改约 200 处文档键位并需放宽菜单块机检（单字符键正则），收益低于回归面；替代方案是分组 + `/` 筛选（本迭代落地） | 不做 |
