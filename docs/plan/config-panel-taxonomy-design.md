# 配置面板分类与描述设计（TUI 与 Web 共用一套概念）

> **关联**：[`llm-settings-nesting-design.md`](llm-settings-nesting-design.md)（`llm_settings.json` 纵切）；设计图样 [`config-panel-mockup/index.html`](config-panel-mockup/index.html)（Web）、[`tui.html`](config-panel-mockup/tui.html)（TUI 全层级）。
> **范围**：TUI 菜单与面板层级、Web 配置面编排、两渠道共用的概念与文案来源。**不含**新增可编辑项、改写入语义、改配置文件结构（见纵切设计）。
> **两渠道**：终端与浏览器表现形式不同（排布、键位、组件形态），但**域、组、显示名、标记口径、说明文案同源**。

---

## 1. 目标

1. **一套概念三渠道共用**：域、组、入口名、标记与说明只有一个来源，TUI 与 Web 只是排布不同。
2. **TUI 层级清晰**：主菜单 → 二级 → 三级（→ 线路面板），高频操作不超过两层。
3. **Web 按业务域编排**：块的顺序、标题、说明、默认值全部由服务端下发，前端不持有中文文案表。
4. **可增长**：新增开关/入口只改注册表与声明表，面板与文档自动跟随。

---

## 2. 共用概念（单一来源）

### 2.1 域（一级分区，Web 用；TUI 以菜单分组体现）

| 域键 | 上屏标题 | 域说明 | 收纳内容 | TUI 对应入口 |
|:--|:--|:--|:--|:--|
| `report_content` | 报告内容 | 改这里会改变报告里出现什么：哪些章出现、章内追加什么、整章回放是否启用 | 顶层章节 + LLM 章节（含辩论子项）+ 默认关闭的整章 + 关联产物 + 章节内容组（按报告位置分六组） | `[C]` 全部、`[S]`（六个内容组） |
| `presentation_mechanism` | 呈现与机制 | 只改呈现口径、匿名化与内部机制/诊断接缝：内容主体不变或仅影响入口显隐 | 匿名化 + 呈现与交互组（含报告页追问）+ 机制与质量组 | `[G]`→`[A]`、`[S]`（后两组） |
| `data_and_routes` | 数据与线路 | 数据从哪读、跟什么基准比、LLM 走哪条线路 | 目录与文件名 + 对比基准指数 + 多链线路 | `[G]`→`[D]/[F]/[O]`、`[G]`→`[I]`、`[G]`→`[L]`（线路） |
| `llm_run` | LLM 运行 | LLM 调用的运行约束（并发/重试/预算） | 运行参数 6 项 | `[G]`→`[L]`（1-6） |
| `ops_diagnostics` | 运行与诊断 | 日志写盘与控制台输出、日志查看器默认筛选；级别与轮转在下次启动生效 | 日志设置 6 项（见 [`logging-config-design.md`](logging-config-design.md)） | `[D]`→`[L]` |

域与 TUI 菜单**不一一对应**：TUI 按"操作位置"（章节 / 开关 / 全局设置）组织，Web 按"意图域"组织；两者共用同一批**条目名**与**标记口径**，不共用排布。

### 2.2 组（按报告位置 / 章节类型）

`[S]` 的组按**报告里在哪看**划分（持仓与交易 / 市场与估值 / 基金与风格 / 事件与摘要 / 呈现与交互 / 机制与质量）；`[C]` 的组按**章节类型**划分（默认关闭的整章）。**每组归属且仅归属一个面板**（声明见下）。

| 顺序 | 组键 | 上屏标题（按报告位置） | 所属面板 | 项数 |
|:--|:--|:--|:--|--:|
| 1 | `portfolio` | 💼 持仓与交易（成本、申赎状态、成本收益、风险调整） | `[S]` | 4 |
| 2 | `market` | 📈 市场与估值（温度、估值分位、景气度、危机回放） | `[S]` | 4 |
| 3 | `fund_style` | 🧩 基金与风格（候选比较、行业 Beta、因子目录） | `[S]` | 3 |
| 4 | `event_summary` | 📰 事件与摘要（事件窗、情绪热点、数据质量、本期要点） | `[S]` | 4 |
| 5 | `presentation` | 🧭 呈现与交互（图表轴值 / 报告页追问） | `[S]` | 2 |
| 6 | `mechanism` | ⚙ 机制与质量（提示词注入 / 输出评级） | `[S]` | 3 |
| 7 | `standalone` | 📑 独立章节与回放（新增整页签或多期回放） | `[C]` | 4 |

辩论两项（`llm_debate_procon` / `llm_debate_conditional`）**不属任何组**：它们不新增章节、也不渲染独立块，只改变智囊团章内的生成内容，因此在 `[C]` 里作为「智囊团深度复盘」的子项呈现（编号 `7.1` / `7.2`）。

组内共 24 项（4+4+3+4+2+3+4），加上作为 `[C]` 子项的辩论 2 项，合 26 项功能开关。S 的组按「报告里在哪看」排序；`crisis_replay` 属 `market`（它扩展「组合历史走势+回撤」章的危机块）。

`PANEL_GROUPS` 声明给出"组 → 面板"的唯一归属，两面板各自只渲染自己的组；覆盖完整性可断言（每组恰属一个面板）。

### 2.3 条目名（TUI 逐字等于 Web 标签）

| 条目 | 统一名称 |
|:--|:--|
| 顶层章节 | 基金深度分析 / 市场新闻 / 组合历史走势+回撤 / 组合演进 / 行动建议 |
| 目录 | 持仓信息目录 / 持仓信息文件名 / 报告输出目录 |
| 指数 | 对比基准指数 |
| 匿名化 | 持仓匿名化（代码 / 名称脱敏） |
| LLM | LLM 设置（运行参数 / 多链线路）、LLM 分析章节、多链线路优先级 |
| 索引 | 配置入口地图 |

### 2.4 标记口径（三渠道同义）

| 标记 | 判定 | 呈现 |
|:--|:--|:--|
| 「影响报告」 | `affects_report` 为真（含报告章节、LLM 模块：关闭即整章隐藏） | Web 行末同列徽标；TUI 用「（影响报告）」纯文本 |
| `⚗` | `experimental` 为真 | 两渠道行首/行尾固定位置 |
| 「已改」 | 当前值 ≠ `defaults` | Web 行尾 `✻`；TUI 行尾 `*`；两渠道以同一对象（`defaults`）为比较基准 |
| 顺序 | 固定为 `⚗ › 影响报告 › 已改` | 行末区右对齐、不随标签长度漂移 |

### 2.5 文案来源

- 组标题、组说明、条目显示名、一句话说明、出厂默认值：**注册表**（`FeatureSwitchDef` 六字段 + `needs_hint`）。
- 域标题与域说明：`DOMAIN_LABELS` / `DOMAIN_HINTS`。
- 路径 / 章节 / 调优项的说明：服务端声明表与 `LLM_TUNING_SPECS.hint`。
- 前端与 TUI 渲染层**不持有**任何中文标签或说明表。

## 3. TUI 设计

### 3.0 层级导航与键语义

```
主菜单（一级 · 14 项）
├─ 生成报告      [E] [B] [L] [W]
├─ 数据与查看    [Q] [1] [2] [3]
├─ 配置
│   ├─ [C] 报告章节显隐    二级 · 数字 1-16（顶层 5 / LLM 7 / 默认关闭的整章 3 / 关联产物 1）
│   │   └─ 7.1 / 7.2         智囊团章生成选项（辩论两项，子项编号）
│   ├─ [S] 报告章节内容呈现  二级 · 数字 1-20（持仓与交易 4 / 市场与估值 4 / 基金与风格 3 / 事件与摘要 4 / 呈现与交互 2 / 机制与质量 3）
│   ├─ [G] 全局设置        二级 · 字母键 H/F/O/L/I/A/M（四组：目录与文件 / LLM 调优 / 基准与呈现 / 索引）
│   │   ├─ [L] LLM 设置         三级 · 数字 1-7 · 0 返回
│   │   │     ├─ 1-6 运行参数        输入新值（范围校验）
│   │   │     └─ 7 多链线路优先级    四级 · 输入两个编号交换
│   │   ├─ [D]/[F]/[O]          目录 / 文件名 / 输出目录
│   │   ├─ [I] 对比基准指数     增删 / 重置
│   │   ├─ [A] 持仓匿名化       数字 1-4 选档
│   │   └─ [M] 配置入口地图     只读打印
│   └─ [R] 刷新配置
└─ 诊断与排查    [D]      二级 · 字母键 L/V/H/T（默认 T）· 0 返回
                ├─ [V] 运行日志
                ├─ [H] 数据源健康历史
                ├─ [T] 系统自检（恒上屏）
                └─ [L] 日志设置（三级 · 数字 1-6）
```

| 层级 | 键的类型 | 用途 | 返回 |
|:--|:--|:--|:--|
| 一级主菜单 | 字母 / 数字（E/B/L/W/Q/1/2/3/P/S/G/R/D） | 进入功能 | `0` / `X` / Ctrl+C |
| 二级面板 | **数字编号**（`[C]` 1-16、`[S]` 1-20）或**字母键**（`[G]` H/F/O/L/I/A/M、`[D]` L/V/H/T） | 切换章节/开关，或选子项 | `0` 回主菜单 |
| 子项编号 | **十进制**（`7.1` / `7.2`） | 只用于某章节下的生成选项，章节编号保持稳定 | 不单独返回，仍在 `[C]` |
| 三级面板 | 数字编号（`[G]`→`[L]` 1-7） | 改一个值或再进一层 | `0` 回上一级 |
| 四级（线路） | 两个数字（如 `3 1`） | 交换两条线路优先级 | 回车返回 |

**返回规则（遵循 `DESIGN-TUI.md` 键分工）**：

| 面板层级 | 末项固定为 | 返回目标 | Esc |
|:--|:--|:--|:--|
| 二级（`[C]` / `[S]` / `[G]` / `[D]`） | `0. 返回主菜单` | 主菜单 | 同 `0`（不退出程序） |
| 三级（`[G]`→`[L]`） | `0. 返回全局设置` | `[G]` 二级面板 | 同 `0` |
| 四级（线路面板） | `0. 返回 LLM 设置` | `[G]`→`[L]` | 同 `0` |

- 每个面板的最后一项恒为 `0`，且文案按"上一层"命名（不是统一的"返回"）。
- 子项（`7.1`/`7.2`）不占返回位，输入后仍停在同一面板。
- 返回后重绘上一层面板，用户可继续操作（不必回到主菜单再进）。

四条容易混淆的边界：

1. **`[C]` 的 16 个编号是"章节显隐与章节类产物"**：1-5 顶层章节、6-12 LLM 章节、13-15 默认关闭的整章、16 关联产物（调仓模拟报告页签）；`7.1`/`7.2` 是第 7 项（智囊团）的生成选项，不算独立章节。
2. **`[S]` 的 20 个编号是"章节内内容"**：按报告位置分六组——持仓与交易 4、市场与估值 4、基金与风格 3、事件与摘要 4、呈现与交互 2、机制与质量 3；LLM 章节、默认关闭的整章与关联产物只在 `[C]` 中出现。
3. **`?编号` 不换层级**：面板内只读查询，打印说明后回到同一提示符，不写配置。
4. **编号随组序派生**：两面板的编号都由所属组的顺序与注册表顺序派生；稳定入口是键名（`?键名` / `键名=on|off`）。

### 3.1 主菜单：14 项，四组

```
── 生成报告 ──          [E] [B] [L] [W]
── 数据与查看 ──        [Q] [1] [2] [3]
── 配置 ──              [C] [S] [G] [R]
── 诊断与排查 ──        [D] 诊断与排查（设置 / 日志 / 健康 / 自检）
                        [X] 退出（0 亦可）
```

配置组四项（标签显示宽均 ≤ 48，80 列不折行）：

```
  [C] 报告章节显隐（顶层 / LLM / 整章 / 关联产物）  ← 44
  [S] 报告章节内容呈现                             ← 16
  [G] 全局设置（目录 / LLM 调优 / 基准与呈现 / 索引）  ← 45
  [R] 刷新配置
```

定位与边界：

| 项 | 管什么 | 不管什么 |
|:--|:--|:--|
| `[C]` | **报告章节显隐**：决定已经登记的章节是否出现（顶层 5 / LLM 7 / 默认关闭的整章 3 / 关联产物 1），以及智囊团的生成选项（`7.1`/`7.2`）；**不增删章节、不改章节顺序** | 章内追加块（在 `[S]`）；章节顺序（由 `config.json` 的 `report_section_order` 决定，不在面板内编辑） |
| `[S]` | **报告章节内的内容与呈现**：按报告位置分六组（持仓与交易 4 / 市场与估值 4 / 基金与风格 3 / 事件与摘要 4 / 呈现与交互 2 / 机制与质量 3） | 章节显隐与整章开关（在 `[C]`） |
| `[G]` | 目录与文件名、LLM 运行参数与多链线路、对比基准指数、持仓匿名化、配置入口地图 | 章节与章内开关 |
| `[D]` | 诊断入口：运行日志 `V`、数据源健康历史 `H`、系统自检 `T`（恒上屏，无开关） | 章节、开关与全局配置（本层只做入口聚合） |
| `[R]` | 重读全部配置文件 | — |

`[C]` 面板结构（16 项 + 两个子项）：

```
  ── 报告章节 ──
   ── 顶层章节 ──
    1. 基金深度分析            [启用]
    2. 市场新闻                [启用]
    3. 组合历史走势+回撤        [启用]
    4. 组合演进                [启用]
    5. 行动建议                [启用]
   ── LLM 章节 ──
    6. 全球政经局势            [启用]
    7. 智囊团深度复盘          [启用]
       7.1 辩论-正反辩论        [关闭]
       7.2 辩论-条件推理        [开启]
    8. 财经新闻热点与持仓关联   [启用]
    9. 持仓体检报告            [启用]
   10. 穿透深度分析            [启用]
   11. 生成后自检              [启用]
   12. 持仓变动复盘归因        [启用]
   ── 默认关闭的整章 ──
   13. 调仓纪律回放            [启用]
   14. 持仓变动复盘            [启用]
   15. 个股基本面              [启用]
   ── 关联产物 ──
   16. What-if 交易成本对比    [启用]（仅调仓模拟报告）
    0. 返回主菜单
```

- 四块来源不同但语义统一：顶层章节写 `config.json` 的 `enable_*`，LLM 章节写 `llm_settings.enabled_llm`，默认关闭的整章与关联产物写 `features.json`；面板不暴露来源差异。
- 本面板只切换显隐：章节集合与顺序由注册表与 `report_section_order` 决定，面板不提供增删或排序。
- **关联产物**只影响「调仓模拟」报告的页签（成本对比），不改变主报告章节；行尾标注产物归属。
- 危机回放不属本面板：它扩展「组合历史走势+回撤」章的危机块，归 `[S]` 的「市场与估值」组。
- 「影响报告」语义在面板顶部统一说明一次（这些项关闭即整章不出现），不在每行重复徽标。
- 子项（`7.1`/`7.2`）只在智囊团启用时可切换；智囊团关闭时置灰并提示"启用第 7 项后可切换"。
- 输入 `7.1` / `7.2` 直接切换子项，输入 `7` 切换章节本身。

### 3.2 `[G]` 二级：7 项

```
  ── 全局设置 ──
     ── 目录与文件 ──
       1 [H] 持仓信息目录
       2 [F] 持仓信息文件名
       3 [O] 报告输出目录
     ── LLM 调优 ──
       4 [L] LLM 设置（运行参数 1-6 + 7 多链线路）
     ── 基准与呈现 ──
       5 [I] 对比基准指数
       6 [A] 持仓匿名化（代码 / 名称脱敏）
     ── 索引 ──
       7 [M] 配置入口地图（各配置项所在菜单）
       0 返回主菜单
```

四个分组标题（目录与文件 / LLM 调优 / 基准与呈现 / 索引）只影响排版（键位、层级与返回语义不变），视觉与首页分组同款：`── 组名 ──` + 结构色（蓝 + 粗），统一经 `text_layout.group_heading()` 产出、组间空行分隔。七项直挂二级、无中间子面板——同一配置只有一条入口路径；新增项必须占用一个新字母并归入上述四组之一。选择提示、无效输入提示与面板标题（「全局设置」）覆盖全部 7 键。`[I]` `[A]` 的面板本体与写路径（`edit_ops` 的 `comparison_indices` / `anonymization.mode`）独立于入口层级。

### 3.3 `[G]` → `[L]` 三级：7 项

```
  ── LLM 设置 ──
   1. thinking 模块并发上限（当前 2）
   2. LLM 模块并发线程数（当前 3）
   3. 单请求重试次数（当前 2）
   4. 整链失败后的重试等待（秒）（当前 30）
   5. LLM 总时间预算（秒）（当前 0）
   6. LLM 日费用上限（当前 0）
   7. 多链线路优先级（2 条，当前链首 deepseek-main）
   0. 返回全局设置
```

1~6 为数值编辑：输入新值即写盘，超出范围直接拒绝；7 为**入口**——进入线路面板（按链序展示 + 输入两个编号交换），返回后回到本面板。线路面板与写路径独立于本面板。行尾摘要给出线路条数与链首，不进第四级即可判断链序。

### 3.4 `[S]` 面板与编号

| 5-8 | 📈 市场与估值 | 4 |
| 9-11 | 🧩 基金与风格 | 3 |
| 12-15 | 📰 事件与摘要 | 4 |
| 16-17 | 🧭 呈现与交互 | 2 |
| 18-20 | ⚙ 机制与质量 | 3 |

面板不出现 LLM 章节、整章与关联产物（在 `[C]`）；系统自检恒上屏、无开关；末项为 `0. 返回主菜单`，面板底部一行提示「章节显隐见 [C]」。稳定入口仍是键名：`?键名` 查询、`键名=on|off` 赋值。

### 3.5 `[D]` 二级：诊断与排查

```
  ── 诊断与排查 ──
   1 [L] 日志设置（级别 / 轮转 / 查看器）
   2 [V] 运行日志（可按级别筛选）
   3 [H] 数据源健康历史
   4 [T] 系统自检（环境 / 配置 / 目录 / 数据源）  ← 回车默认
   0 返回主菜单
```

`[L]` 三级（数字编号，`0` 返回诊断与排查）：

```
  ── 日志设置 ──
   1. 写盘级别（当前 INFO）
   2. 控制台级别（当前 INFO）
   3. 单文件上限 MB（当前 10）
   4. 备份份数（当前 5）
   5. 查看器默认级别（当前 INFO）
   6. 查看器首屏行数（当前 500）
   0. 返回诊断与排查
```

- 日志设置写入独立的 `logger.json`（详见 [`logging-config-design.md`](logging-config-design.md)）；级别与轮转改动下次启动生效，查看器两项即时生效。
- `[T]` 恒上屏：不设功能开关，也不受任何开关门控；本层**缺省项为 T**（回车直接进入系统自检）。
- 返回语义：`0` 回主菜单；Esc 同义。

### 3.6 键位纪律

- 顶层字母分配：配置组取 `C`/`S`/`G`/`R`（`C`=Chapter 章节显隐、`G`=Global），诊断组取 `D`；`[G]` 二级取 `H`/`F`/`O`/`L`/`I`/`A`/`M`，`[D]` 二级取 `V`/`H`/`T`/`L`。同一字母可同时出现在不同层级（`D` 在主菜单为「诊断与排查」、在 `[G]` 内为「持仓信息目录」；`L` 在主菜单为「生成完整报告」、在 `[G]` 内为「LLM 设置」），层级间互不冲突。
- `default_menu_key` 的合法取值即主菜单键集合（出厂 `L`）；取值为不存在的键时回落首项 `E`。
- **分组标题视觉纪律**：主菜单分组、面板内分组/分类标题统一用 `style_heading`（蓝色粗体，结构色），面板横幅同色系；分组标题不承载状态语义，不得用绿/黄/红等状态色。
- 二级面板同样以**数字为第一入口**（`1..N` 连续），**字母为直达别名**（`H/F/O/L/I/A/M`、`L/V/H/T`），两通道等价（遵循 `DESIGN-TUI.md`：字母不得成为唯一入口）。

### 3.7 分组标题视觉纪律（全局同款）

分组标题是**结构信息**，不是状态信息——主菜单四组、`[C]` 四块、`[S]` 六组、`[G]` 四组，以及此后新增的任何面板分组，**一律同色调、同风格**，由单一产出点保证：

| 维度 | 规则 |
|:--|:--|
| 产出点 | `text_layout.group_heading(title, columns, prefix=...)`——渠道不得自造分隔符、裸色组名或另写缩进 |
| 形态 | `── 组名 ──`（与首页分组同款） |
| 配色 | `style_heading`：蓝 + 粗（结构色），**禁用**绿/黄/红等状态色 |
| 折行 | 按给定列宽折行；面板内传面板内宽（`inner_width(columns)`），窄屏不撑破右边框 |
| 间距 | 组间一个空行，组内条目紧随组标题 |
| 分支 | `[C]` 与 `[S]` 的组标题带 `（N/M 开）` 计数，`[G]` 与主菜单不带——计数属组内统计而非组标题职责之外的内容 |

`[G]` 的四组即「目录与文件 / LLM 调优 / 基准与呈现 / 索引」；Web 侧对应同一色调（`--primary`，见 §4.9），仅表达形态随渠道（浏览器用分隔线 + 结构色文字，终端用 `──` 装饰）。

## 4. Web 设计（同理念，按浏览器特性表达）

### 4.1 设计原则

| 原则 | 落点 |
|:--|:--|
| **域即分区** | 一级分区 = 业务域（报告内容 / 呈现与机制 / 数据与线路 / LLM 运行 / 运行与诊断），与 TUI 的菜单入口同源不同排布 |
| **控件即语义** | 布尔用勾选、互斥用单选、自由文本用输入框、数值用数字框、集合用列表 + 动作按钮；不把可编辑项塞进下拉或弹窗 |
| **文案零硬编码** | 标签、说明、默认值、分组标题全部由服务端下发；前端只做渲染与交互 |
| **改动可回滚** | 即时保存类失败自动回滚并就地报错；显式保存类保留输入值供重试 |
| **无编号** | 数字编号是终端渠道的寻址方式；Web 用控件与筛选寻址 |
| **可深链** | 每个域有锚点（`#domain-<key>`），可直接分享到某一分区 |

### 4.2 页面结构

```
工具条（sticky）：标题 · 项数/已改数 · 说明密度 · 标记 · 主题 · 关键词筛选
域导航（chips，随滚动高亮当前域）
┌ 域分区 ────────────────────────────────┐
│ 域标题 + 域说明 + TUI 对应入口          │
│  ├ 块：标题 + 计数（N 项 · M 开）       │
│  │   ├ 行：控件 + 标签 + 标记 + 说明     │
│  │   └ 块级错误区（失败时就地显示）      │
└────────────────────────────────────────┘
页脚：生效时机说明（配置/日志/计价参考）
```

### 4.3 编排契约：`domains`

```json
"domains": [
  {"key": "report_content", "title": "报告内容", "hint": "改这里会改变报告里出现什么…",
   "tui": "TUI：[C] 报告章节显隐 + [S] 报告章节内容",
   "blocks": ["sections", "llm", "standalone_chapters", "standalone_related", "features.analysis"]}
]
```

- 五个域与块的完整对应见 §2.1；块顺序即渲染顺序。报告内容域的「默认关闭的整章」与「关联产物」分为两个块（后者仅影响调仓模拟报告）。
- `features.<组键>` 由 `surface.features.groups` 提供数据；其余块查渲染器表。
- 渲染器返回 `null` 即跳过该块（数据为空不渲染空壳），域内块全空则该域不出现。
- `tui` 字段只作阅读导引（"这个域在终端里对应哪几个入口"），不参与交互。

### 4.4 数据契约

| 键空间 | 覆盖 | 来源 |
|:--|:--|:--|
| `labels` | 目录 3、顶层章节 5、功能开关 26、`enabled_llm.<模块>` 7 | 声明表 + 注册表 + 模块注册表 |
| `descriptions` | 同上全覆盖（调优项说明随 `llm_tuning[].hint`） | 声明表 + 注册表 `desc` |
| `defaults` | 布尔与数值类：开关 26、章节 5、LLM 模块 7、调优 6 | 注册表默认值 / `LLM_TUNING_SPECS` |
| `features.needs_hint` | 需默认显副行的 flag 清单 | 注册表 |
| 组标题与分组项数 | 持仓与交易 4 / 市场与估值 4 / 基金与风格 3 / 事件与摘要 4 / 呈现与交互 2 / 机制与质量 3；默认关闭的整章 3 / 关联产物 1 | `GROUP_LABELS` + 声明表 |
| `anonymization.labels` | 4 档 | `ANONYMIZATION_MODE_DESCRIPTIONS` |
| `llm_providers.strategy_label` / `order_is_chain` | 4 种策略中文名 + 顺序是否等于链序 | 策略中文表 |
| `logging` | 级别枚举、当前值、范围（MB/份数/行数） | `logger.json` 与默认值 |
| `reference`（只读） | 计价参考文件路径与说明（不进编辑面） | `llm_pricing_ref.json` 元信息 |

### 4.4.1 块 id ↔ 渲染器 ↔ 空数据

| 块 id | 渲染器 | 空数据处理 |
|:--|:--|:--|
| `paths` | 目录表单（文本 + 保存） | 不出现 |
| `sections` | 布尔组 | 不出现 |
| `llm` | 布尔组 + 智囊团子项 | 不出现 |
| `features.<组键>` | 布尔组（取 `features.groups[i]`；组键为 `analysis` / `presentation` / `mechanism`） | 组内 0 项不出现 |
| `standalone_chapters` | 布尔组（默认关闭的整章：调仓纪律回放 / 持仓变动复盘 / 个股基本面） | 0 项不出现 |
| `standalone_related` | 布尔组（关联产物：What-if 交易成本对比，行尾标产物归属） | 0 项不出现 |
| `anonymization` | 单选组 | 不出现 |
| `indices` | 列表 + 添加表单 | 至少有添加表单才渲染 |
| `providers` | 优先级列表 + ▲▼ | 无线路则不出现 |
| `tuning` | 数字框 + 保存 | 不出现 |
| `logging` | 下拉 + 数字 + 保存 | 不出现 |
| `reference` | 只读信息行（文件路径 + 说明） | 固定渲染（不随数据为空消失） |

### 4.5 控件与保存语义

| 类型 | 控件 | 保存 | 失败处理 |
|:--|:--|:--|:--|
| 布尔（章节/开关/LLM 模块） | 勾选框 | **即时保存**（乐观更新） | 回滚勾选状态 + 块级错误区显示服务端中文 |
| 枚举（匿名化、日志级别） | 单选 / 下拉 | 即时保存 | 回滚选中项 + 错误区 |
| 文本（目录/文件名/路径） | 输入框 + 「保存」 | 显式保存 | 保留输入值，错误区提示原因 |
| 数值（运行参数、日志轮转） | 数字框 + 「保存」 | 显式保存 | 保留输入值并提示范围（来自 `min`/`max`） |
| 集合（基准指数） | 列表 + 添加/删除 | 动作即保存 | 操作失败回滚列表并提示 |
| 排序（多链线路） | ▲▼ 按钮 | 动作即保存 | 失败回滚顺序并提示 |
| 只读（计价参考 `reference`） | 文本行（路径 + 说明） | 不可编辑 | —（不涉及写入） |

- 保存统一走 `POST /api/config/edit`（白名单 + 校验单点），Web 不另写校验。
- 每次保存成功在该行给出短暂「已保存」态；不可用时整块禁用并说明原因。

### 4.6 状态、筛选与反馈

| 机制 | 行为 |
|:--|:--|
| 块计数 | `N 项 · M 开`（枚举/集合类显示为 `N 档` / `N 个基准`） |
| 已改计数 | 工具条显示「已改 N 项」，与每行 `✻` 同源（`defaults` 比较） |
| 关键词筛选 | 按标签/说明/键名实时过滤；空块与空域自动隐藏，清空即恢复 |
| 空态 | 数据缺失的块不渲染；整页加载失败显示「配置加载失败，请稍后重试」 |
| 失败定位 | 错误显示在**对应块内**（不打断其他块操作），面板顶部只保留同源校验等全局错误 |
| 生效时机 | 配置/章节/开关即时生效；日志级别与轮转提示"下次启动生效"；计价参考只读 |

### 4.7 无障碍与安全

- 每个控件有 `<label for>`；块容器 `role="group"` + `aria-label`；错误区 `role="alert"`。
- 键盘可达：勾选/输入/按钮均按 Tab 顺序；焦点环用 `--focus`，不自定义 outline。
- 全部文案用 `textContent` / DOM API 渲染，**禁止 `innerHTML`**（XSS 纪律）。
- 写操作遵循同源校验约定；不在前端拼接文件名或路径。

### 4.8 响应式与主题

- ≤720px 单列：工具条换行、域导航横向滚动、输入控件占满行宽。
- 亮色为源、暗色成对；所有新元素只用 `DESIGN.md` token（见 4.9），不自造色值。
- 打印不属该面板场景，不做打印样式。

### 4.9 视觉规格

| 元素 | 规格 | 取值 |
|:--|:--|:--|
| 域分区 | 相邻域上间距 + 分隔线 | `margin-top: 26px; padding-top: 22px; border-top: 1px solid var(--border)` |
| 域标题 | 卡片/小节标题档（16px），左侧品牌蓝竖线（单强调色） | `16px / 1.4`，`padding-left: 10px; border-left: 3px solid var(--primary)` |
| 域说明 / TUI 导引 | 脚注档，次要墨色 | `12px / 1.5`，`var(--text-secondary)` |
| 项说明副行 | 脚注档，与控件文字左对齐 | `12px / 1.5`，`margin-left: 24px` |
| 块标题（分组） | 结构色，与 TUI 分组标题同色调；组间用分隔线（不是 `──` 装饰） | `13px / 1.4`，`var(--primary)` |
| 「影响报告」徽标 | 中性徽标（1px 边框 + 次要墨色），不承载状态语义 | `var(--text-secondary)`，明暗自动成对 |
| `⚗` 实验项 | 状态语义（警告色） | `var(--warn)` |
| `✻` 已改 | 强调语义 | `var(--primary)` |

### 4.10 与 TUI 的差异（同理念、不同表达）

| 维度 | TUI | Web |
|:--|:--|:--|
| 寻址 | 数字编号 / 字母别名 | 域锚点 + 关键词筛选 |
| 分区轴 | 按操作位置（P/S/G/D） | 按意图域（五个域） |
| 开关控件 | 输入编号切换（持仓与交易 / 市场与估值 / 基金与风格 / 事件与摘要 / 呈现与交互 / 机制与质量） | 勾选即时保存 |
| 数值修改 | 输入编号 → 输入新值 | 数字框 + 保存 |
| 失败反馈 | 面板内一行 `[!]` | 块级错误区 + 行内回滚 |
| 导航 | 上级返回 | 域跳转 + 深链 |
| 不共用 | 终端键位与配色 | 数字编号 |

### 4.11 明确不做

| 不做 | 理由 |
|:--|:--|
| 在 Web 引入 TUI 的数字编号 | 编号是终端寻址手段；浏览器用控件与筛选更快 |
| 把 `llm_pricing_ref.json` 做成可编辑面 | 参考数据，随供应商调价更新；只提供只读入口与路径提示 |
| 在 Web 暴露缓存清理 | 属诊断操作，保留在 TUI `[3]` 与 CLI |
| 前端自持标签/说明字典 | 文案必须服务端下发，避免双源漂移 |

## 7. 配置文件全景与边界

### 7.0 演进策略（不做任何旧版兼容）

配置与持久化数据的结构变更，**一律不为旧版本留兼容**。适用范围与处理方式：

| 对象 | 处理 |
|:--|:--|
| **其他结构的配置文件**（config / features / llm_settings / llm_providers / logger 等） | 结构版本不符即拒绝加载并提示重新生成；不提供结构转换脚本、不保留双读分支 |
| **不在当前结构内的配置项 / 键名** | 不解析、不映射、不静默忽略；文档只保留键位对照供重新生成时人工参考 |
| **非当前格式的缓存数据**（`data/cache/` 各前缀 JSON） | 不读取其他格式；缓存可再生，直接清理（`clear_by_group` / 删除目录），由程序按当前结构重建 |
| **其他结构的数据文件**（快照、账本、实验统计、持久化中间产物） | 不做字段兼容与补全；结构不符即忽略该文件或重建，不做隐式转换 |

配套四条硬约束：

1. **重新生成**：文件缺失或结构版本不符，由默认配置生成器产出新文件；用户值不随重建携带，按文档自行重设。
2. **生成器同批更新**：任何结构变更必须同步修改默认生成器（模板、注释、默认项），否则视为改动未完成。
3. **版本字段只做拒绝校验**：缺失或不匹配即报错并给出重建指引，不做升级解释。
4. **代码不写兼容分支**：不保留 `if old_version` / 字段别名映射 / 静默兜底；兼容代码本身即缺陷来源。

### 7.1 八份文件的职责边界（六份配置 + 两份密钥）

| 文件 | 内容 | 归属 | 结论 |
|:--|:--|:--|:--|
| `config.json` | 路径、章节开关、数据源、缓存、调度、通知、基准等 42 键 | 用户可编辑 | 保留，内部整理见 7.2 |
| `features.json` | 功能开关的覆写层（22 项覆写 / 26 项注册） | 面板写入 | 保留：覆写层语义清晰，缺键即出厂默认 |
| `llm_settings.json` | LLM 模块参数与运行约束 | 面板写入 | 保留；结构按 [`llm-settings-nesting-design.md`](llm-settings-nesting-design.md) 纵切 |
| `llm_providers.json` | 多链线路清单与优先级 | 面板/CLI 写入 | 保留：多链是独立子系统 |
| `llm_key.json` / `data_key.json` | 模型与数据源凭据（两份） | 仅手填 | 保留且**永不合并**：密钥与配置分离是安全边界（git 忽略） |
| `logger.json` | 日志级别、轮转、查看器默认项 | 面板写入 | 新增：运行诊断域独立，且需环境变量临时覆盖 |
| `llm_pricing_ref.json` | LLM 计价参考：币种/时区/峰谷规则 + 各模型单价 | 仅手填 | 新增：参考数据（随供应商调价更新），非用户调优项；不进面板 |

原则：**一份文件对应一个用户可理解的域**；密钥单独；**参考数据（如计价表）单独成文件**；不按"代码模块"拆分。

### 7.2 `config.json` 的三处内部问题（取舍结论）

| 问题 | 事实 | 判定 |
|:--|:--|:--|
| 同一组配置分布在扁平键与嵌套段两处 | `market_hour_aware` / `market_hour_ttl` 与 `market_hours` 平级混放（各 7 处引用）；`batch` 与 `batch_rate_limit` 两个平行段（18 处引用） | **暂不合并**：收益仅是形式统一，需重新生成 + 生成器模板 + 文档与测试同步；留待进入「域即文件」阶段统一处理 |
| 四个内部文件指针混在用户配置里 | `llm_key_file` / `llm_settings_file` / `llm_providers_file` / `data_key_file`（5~21 处引用） | **保持结构**：它们是路径覆盖能力而非日常配置；在文档中标为「高级/内部」即可 |
| 空字典段易被误认为"可配" | `preferred_provider` / `redemption_limits` / `fund_fee_fallback` / `user_fund_benchmarks` 默认为 `{}` | **记录为模板质量事项**：给示例值或注明"留空即用内置默认"；不与结构重建同批 |

同理保持不动：`news_top_count` 与 `news_sources` 分离（38 处引用）、`comparison_indices` / `comparison_candidates` / `whatif_benchmark_index` 三处分离（语义不同：基准池 / 候选池 / What-if 基准）。

### 7.2.1 候选整理清单（备查，非排期）

下表把 7.2 的三类问题列为可选动作，仅作将来评审的输入——**无实施动作、无排期**；任一项启动前需单独评审（结构变更按 7.0：不做旧版兼容，直接重新生成）。

| 候选动作 | 引用量 | 重建成本 | 收益 | 触发条件 |
|:--|--:|:--|:--|:--|
| `market_hour_aware` / `market_hour_ttl` 合并为 `market_hours.{aware,ttl}` | 14 处（7+7） | 中：生成器模板 + 文档/测试 | 同类项在一处，扁平键减 2 | 进入「域即文件」阶段 |
| `batch_rate_limit` 合并为 `batch.rate_limit` | 18 处 | 中：同上 | 两个平行段合一 | 同上 |
| 四个文件指针收进 `paths.*` | 5~21 处/键 | 低：生成器模板 + 键名映射 | 用户配置区与内部 plumbing 分开 | 文档标注「高级/内部」后仍被误改 |
| 四个空段补示例或注释 | 0 处代码引用 | 低：仅模板文案 | 消除"看起来可配但为空"的误读 | 随时（作为模板质量项） |
| `news_top_count` 合入 `news.sources`；三处基准键并段 | 38 + 41 处 | 高：面广、语义差异需保留 | 形式统一 | 不作为候选：收益低于成本 |

### 7.3 明确不做的四件事

| 不做 | 理由 |
|:--|:--|
| 合并成单一 `settings.json` | 重建覆盖全部 loader、面板、测试与文档，收益仅"少一个文件"；面板已按域抽象，用户不感知文件名 |
| 按"代码模块"继续拆文件（`scheduler.json`、`datasource.json` 等） | 会让"改一个设置该开哪个文件"更难答；只有**业务域独立**（运行诊断）或**数据类型不同**（参考数据）才单独成文件 |
| 密钥并回主配置 | 安全边界：凭据必须与配置分离且不入库 |
| 给 `config.json` 加 `version` | 仅在结构重建时需要；与该次重建同批加入 |

### 7.4 触发重估的条件

只有出现下列之一才重估本文结构：① 进入「域即文件」阶段（一份文件 = 一个业务域）；② 新增第 7 份用户可编辑文件的需求；③ 扁平键与嵌套段的不一致导致实际误配（有事故/工单）。

### 7.5 配置书写与读取约定（中文注释）

**约束：默认配置生成器一律输出带中文注释的配置文件；所有读取路径一律支持带注释的文件。**

| 角色 | 要求 |
|:--|:--|
| 默认配置生成器（`config.json` / `features.json` / `llm_settings.json` / `llm_providers.json` / `logger.json` / `llm_pricing_ref.json` 及后续新增） | 输出 JSONC 风格（`//` 行注释）：**分类标题 + 每个配置项一句中文说明**；注释不改变数据语义，不允许把值写进注释 |
| 所有读取路径（配置包、`core/logger.py`、`llm/pricing.py`、脚本与 Web） | 必须经统一注释剥离器解析；**禁止**对配置文件直接 `json.loads` 原始文本 |
| 注释剥离器 | 以叶子模块 `core/json_comments.py`（新增，仅标准库）承载，`config/_comments.py` 再导出；日志与计价等 core 级读取因此不必导入 config 包，避免循环依赖 |
| 写入保真 | 写回时保留既有注释（读—改—写链路不得抹掉分类说明与项说明） |
| 校验 | 模板生成测试断言产出含中文注释；读取测试使用带注释样本；新增生成器未带注释视为未完成 |

适用边界：注释只用于解释；机器状态文件（缓存、账本、快照）**不加注释**，仍为纯 JSON。
