> **依据**：[`config-panel-taxonomy-design.md`](config-panel-taxonomy-design.md)（面板与配置文件全景）、[`llm-settings-nesting-design.md`](llm-settings-nesting-design.md)（LLM 配置纵切与计价参考）、[`logging-config-design.md`](logging-config-design.md)（日志配置独立）。

> **约束与契约**：全部轮次受 `technical.md`「架构设计约束」、`DESIGN.md`（Web 视觉）、`DESIGN-TUI.md`（终端交互）约束；每轮的验收表列出对应检查点。

## 0. 全局质量管控

### 0.1 分层门禁

| 层级 | 触发 | 内容 |
|:--|:--|:--|
| P0 批次门禁 | 每轮代码完成后 | `scripts/test-runner.py --mode dev-verify`（核心单元 + 基础场景）；便宜检查（单文件/单目录 pytest、`check-file-length`）随批执行 |
| pre-commit 十守护 | 每次提交 | 代码/文档痕迹、任务编号、语义命名、文档漂移、测试冗余、需求追溯、版本一致、文档链接、行数红线、目录树统计（**不在本地手动重复执行**） |
| P1 合入门禁 | 合并 master 前 | `scripts/test-runner.py --mode verify` |
| P2 发布门禁 | 打版本标签前 | `scripts/test-runner.py --mode regression` + `release.py gate`（含设计护栏、十守护并行、性能门禁） |

### 0.1.1 每轮收尾三件事（缺一不可）

1. **文档同步**：本轮若改动注册表/面板/菜单，必须同批更新 `how-to-config.md`（功能开关表）、`how-to-use-tui-menu.md`（`[S]` 面板编号表与组块标题）、`requirements.md` §11.5、`technical.md` 注册表段、`testplan.md` 对应描述——门禁脚本在提交时校验文档与实现一致，**文档不能留到第 12 轮**（第 12 轮只做最终扫尾与契约登记复核）。
2. **changelog 记一笔**：`docs/managements/changelog.md` 增本轮变更条目（改了什么、为什么、验收证据）。
3. **提交**：`dev-verify` 绿后提交（钩子跑十守护）；提交通过才进入下一轮，失败即停在本轮修复。

### 0.2 测试纪律（每轮必须满足）

- 新增/修改用例标注 marker；edge 用例入 `*_edge.py`；不修改 `data/config/`、`data/holdings/`、`data/state/`（conftest 隔离）。
- 任何触发 LLM 的用例必须 mock；外部网络由 conftest 阻断；报告/编排类用例声明离线桩。
- 断言用结构关系（集合相等 / 覆盖 / 序号连续），不写死可增长集合的条数；浮点用 `pytest.approx`。
- 缺陷修复必须附回归用例（先红后绿）。

### 0.3 「不做兼容」的验收方式

- 代码检索门禁：`src/` 内不得出现 `old_version`、键位别名映射表、静默兜底分支（评审 + grep 抽查，纳入复核清单）。
- 结构不符时的行为：加载失败并给出重新生成指引（不是回落默认）。

### 0.4 回滚单位与策略

- **提交单位 = 轮**：每轮一个可独立 revert 的提交（配置类轮次同时给出"重新生成"步骤，回滚后删文件重建即可）。
- **配置类轮次**（3、4、6、7）：回滚必须验证「删除文件 → 生成器重建 → 启动正常」；备份仅用 `.bak` 单槽。
- **代码类轮次**（8~11）：回滚仅 revert 代码与文档，不涉及数据文件。
- **跨轮依赖**：前置轮未回滚时，后续轮的 revert 顺序必须逆序（14→13→…）。

### 0.5 质量指标（每轮记录）

| 指标 | 口径 | 目标 |
|:--|:--|:--|
| 用例有效性 | 本轮新增/改动的测试 | 无「无断言 / 恒真断言 / 自证用例」；新增分支至少一条断言 |
| 门禁耗时 | `dev-verify` 墙钟 | 不因本轮增长超过 10% |
| 配置错误可定位性 | 非法值/结构不符的报错 | 必须包含「哪个文件、哪个键、合法范围」 |
| 文档一致性 | 漂移检查 | 0 finding |

## 2. 逐轮计划与验收标准

### 第 1 轮：注册表与域模型

**交付**
- `config/_feature_registry.py`：组顺序（`portfolio` / `market` / `fund_style` / `event_summary` / `presentation` / `mechanism` / `standalone`，标题依次为「持仓与交易 / 市场与估值 / 基金与风格 / 事件与摘要 / 呈现与交互 / 机制与质量 / 独立章节与回放」）、`DOMAIN_ORDER`/`DOMAIN_LABELS`/`DOMAIN_HINTS`、`GROUP_DOMAIN`、`PANEL_GROUPS`、`FeatureSwitchDef.needs_hint`；开关集合不含 `doctor_check`；`report_qa` 归 `presentation`。
- `config/features.py`：导出面扩展与文档串口径。
- **文档同批**：`how-to-config.md` 功能开关表（26 项、8 组标题与计数）、`how-to-use-tui-menu.md` `[S]` 面板编号表（7 个 LLM 模块 + 26 项 = 1-33）与组块标题、`requirements.md` §11.5、`technical.md` 注册表段、`testplan.md` 对应描述。

**验收标准**
1. `GROUP_DOMAIN` 键集 = `GROUP_ORDER`；值域 ⊆ `DOMAIN_ORDER`；`PANEL_GROUPS` 覆盖全部组且每组恰属一个面板。
2. 注册表中不存在 `doctor_check`：`grep -rn doctor_check src/python` 命中数为 0（日志与文档若提及须使用语义描述）。
3. `needs_hint` 为布尔；`features.needs_hint` 清单 ⊆ 注册表键。
4. `dev-verify` 绿；语义命名索引与开关注册表用例绿。
5. `check-doc-drift --ci` 绿（开关表/面板编号/分组计数与注册表一致）。

**依赖**：无。
**约束/契约**：开关注册表唯一来源（见 `technical.md` 架构约束）；语义命名纪律。

### 第 2 轮：注释契约

**交付**
- `core/json_comments.py`（叶子模块，仅标准库）；`config/_comments.py` 再导出。
- 全部配置读取改经统一剥离器；写入保留既有注释。

**验收标准**
1. 带 `//` 与 `/* */` 注释的样本可被读取（逐文件用例：config/features/llm_settings/llm_providers/logger/pricing）。
2. 生成器输出含中文分类注释与逐项说明（断言注释行存在且含中文字符）。
3. 读—改—写后注释仍在（round-trip 用例）。
4. `core/logger.py` 不导入 `config` 包（断言导入链无环）。
5. `dev-verify` 绿。

**依赖**：无（剥离器为叶子模块，先行落地）。
**约束/契约**：叶子模块分层；不引入循环依赖。

### 第 3 轮：LLM 配置 v2 结构与默认生成器

**交付**
- `config/_llm_settings.py`：版本校验、展平/反展平、三层缺省合并、未知内容保留；不含其他结构解析。
- `config/_llm_settings_defaults.py`：生成器输出 v2（含 `defaults`/`modules`/`runtime`/`advanced` 与中文注释）。

**验收标准**
1. 删除配置文件后，生成器产出内容与模板逐键一致（生成器测试）。
2. `schema_version` 缺失或 ≠2 时加载失败并给出重新生成指引（用例断言错误信息含文件名与版本）。
3. 三层优先级矩阵（模块值 / defaults / 内置默认）逐一断言通过。
4. 展平视图字段与消费方契约一致（`model_*` / `thinking_*` / `enabled_llm` / `llm_max_*` / `debate` 等）；`llm/` 包无改动仍绿。
5. `dev-verify` 绿。

**依赖**：第 1、2 轮。
**约束/契约**：原子写、路径绝对化、不做旧版兼容（设计 §5）。

### 第 4 轮：LLM 参数校验

**交付**
- `config/_validation_llm.py`：模块参数范围（温度、输出上限、超时、思考预算、effort 枚举、debate 预算）。
- 加载路径回默认 + 告警；面板写入拒绝并提示范围。

**验收标准**
1. 表驱动用例：每个参数各 1 组合法/越界/类型错误，行为符合「加载回默认、保存拒绝」。
2. 报错信息包含键名、当前值、合法范围。
3. 非法值不落盘（写后读回仍为原合法值）。
4. `dev-verify` 绿。

**依赖**：第 3 轮。
**约束/契约**：错误呈现口径与面板一致；不静默裁剪。

### 第 5 轮：生成参数入指纹

**交付**
- `llm/module_fingerprint.py`：模块级「生成参数摘要」（temperature / max_tokens / thinking）作为指纹输入；预检侧与写侧同源。

**验收标准**
1. 调整 `temperature` 或 `max_tokens` → 同模块缓存键变化（用例断言两个键不相等、任一键只对应一种参数组合）。
2. 仅改与生成无关的项（如 `cache`）→ 键不变（避免过度失效）。
3. 预检与写侧键一致（同一函数构造，断言两次调用相等）。
4. 现有指纹用例全绿；`dev-verify` 绿。

**依赖**：第 3、4 轮。
**约束/契约**：指纹唯一事实来源（`module_fingerprint.py`）；缓存统一接口。

### 第 6 轮：计价参考文件

**交付**
- `data/config/llm_pricing_ref.json`（策略 + `models`）。
- `config/_llm_pricing.py`：读取/校验/逐模型合并；`llm/pricing.py` 数据源切换。

**验收标准**
1. 文件缺失 → 仅用内置价（用例断言合并结果等于内置）。
2. 单模型覆盖生效；只覆盖出现的字段（其余取内置值）。
3. 非法条目告警并跳过；`version` 不符拒绝加载并提示重新生成。
4. 相同价格输入下，费用计算结果与基线一致（浮点用容差）。
5. `dev-verify` 绿。

**依赖**：第 2、3 轮。
**约束/契约**：路径绝对化；参考数据不进编辑面；原子写。

### 第 7 轮：日志配置

**交付**
- `data/config/logger.json`（生成器 + 中文注释）。
- `core/logger.py`：启动时读取并创建 handler（路径/级别/轮转/颜色）；env 覆盖。
- `config/_logging.py`：读取/校验/写入（面板共用）。

**验收标准**
1. 缺文件 → 全默认正常工作；非法级别/越界数值 → 告警回落，面板保存被拒。
2. env 覆盖优先级高于文件（用例覆盖 `INVEST_LOG_FILE_LEVEL`）。
3. 轮转参数生效（用临时目录断言 maxBytes/backupCount 传入 handler）。
4. 日志目录不可写 → 主流程继续、控制台有输出。
5. `NO_COLOR`/非 TTY 降级为无色。
6. `dev-verify` 绿。

**依赖**：第 2 轮（注释剥离器）。
**约束/契约**：日志统一、控制台着色、路径绝对化、原子写。

### 第 8 轮：TUI 菜单与分层

**交付**
- `tui/tui_menu.py`：主菜单 14 项（配置组 P/S/G/R、诊断组 D），移除顶层 M/I/A/V/H/T。
- `tui/handlers_config.py`：`[D]` 子菜单（L/V/H/T，缺省 T），`[G]` 七项分组排版，数字主入口 + 字母别名；返回语义按层级。
- `tui/handlers_log.py`：日志设置三级面板。

**验收标准**
1. 菜单项数 14、分组键集与顺序断言；标签显示宽 ≤48。
2. `[G]`→D/F/O/L/I/A/M、`[D]`→L/V/H/T 路由可达（缺省 T）；顶层 M/I/A/V/H/T 无路由。
3. 所有二级/三级面板末项为 `0`，文案分别为「返回主菜单 / 返回全局设置 / 返回诊断与排查 / 返回 LLM 设置」；`[D]` 顺序为 L/V/H/T 且缺省 T。
4. 数字与字母双通道等价（同一项两入口行为一致）。
5. 40/80 列下盒线与提示不超宽；`layout_tier` 仅改版式。
6. 新增用例标注 marker；涉及配置文件写入的用例使用临时目录隔离。
7. `dev-verify` 绿。

**依赖**：第 1、7 轮。
**约束/契约**：`DESIGN-TUI.md` 键分工与提示三段式、术语表；分档只改版式。

### 第 9 轮：TUI 面板内容

**交付**
- `[C]` 报告章节显隐：16 项四块（顶层 / LLM / 默认关闭的整章 / 关联产物）+ `7.1`/`7.2` 子项；来源写路径统一；面板只切显隐，不增删章节、不改顺序。

**验收标准**
1. `[C]` 项数与编号连续（1-16），四块边界正确；`7.1`/`7.2` 可切换；智囊团关闭时子项置灰且提示原因。

3. 四来源写入分别落在 `config.json` / `llm_settings.json` / `features.json` 的正确键（断言文件内容）。
4. 每个开关都有键名展示；`?编号` 详情可读。
5. 新增用例标注 marker；三来源写入用例使用临时配置目录。
6. `dev-verify` 绿。

**依赖**：第 1、3、8 轮。
**约束/契约**：章节注册表驱动；开关注册表唯一来源。

### 第 10 轮：Web 面契约

### 第 11 轮：Web 交互与状态

### 第 15 轮：稳态观测与回退演练

**交付**
- 观测项：配置加载失败日志、日志配置生效记录、计价覆盖告警、指纹变化后的缓存命中率。
- 回退演练：按「不做旧版兼容」策略验证重建路径。

**验收标准**
1. 制造非法配置 → 启动日志包含文件名 + 键 + 原因；程序不静默回落。
2. 删除配置文件 → 生成器重建后启动正常（三个文件逐一验证：`llm_settings.json`、`logger.json`、`llm_pricing_ref.json`）。
3. 清空缓存 → 首轮全量重算，第二轮起命中率恢复正常（观测数值记录在案）。
4. 回退演练：把配置目录整体备份并置为非当前结构样本 → 程序明确拒绝并给出重建指引（不出现静默降级）。
5. 观测项接入现有日志与 `perf_history`（不新增面板）。

**依赖**：第 14 轮。
**约束/契约**：不做旧版兼容（设计文档「演进策略」节）；缓存统一接口。

## 4. 风险与回退

| 风险 | 影响 | 缓解 |
|:--|:--|:--|
| 配置结构导致启动失败 | 高 | 加载失败给出重建指引；打版本标签前用「删除配置 → 生成 → 启动」验证 |
| 指纹变更引发首轮全量重算 | 中 | 属预期；记录耗时与命中率，避免误判为性能退化 |
| Web 面板漏接新块 | 中 | 契约测试「每个块有渲染器」；冒烟脚本覆盖 |
| 文档与实现漂移 | 中 | 每轮结束跑漂移检查；契约档结构测试兜底 |
| 行数红线被突破 | 中 | 新面板放 `handlers_log.py` 或独立模块；`check-file-length` 随批执行 |
| 写回抹掉配置注释 | 中 | 读—改—写 round-trip 用例断言注释仍在（第 2 轮验收） |
| 剥离器引入导入环或读放大 | 中 | 叶子模块不导入配置包；读取路径复用同一实例（第 2 轮验收） |

## 5. 完成定义（DoD）

一轮完成的必要条件（缺一不可）：

1. 交付物齐备，且无「临时兜底分支 / 非当前键位适配代码」。
2. 该轮验收标准逐条有对应测试或检查证据（命令与断言可复跑）。
3. 门禁通过（P0；涉及合并/发布时对应 P1/P2）。
4. 文档触点同步（手册、契约、台账）。
5. 变更记录写入 `changelog.md`，自审问题按 `rf-` 编号登记并闭环。
