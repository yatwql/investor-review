# 持仓录入真机验收执行指引（plan-238 / plan-239）

> 目的：让两条待验收任务（TUI `[U]` 面板、Web「持仓录入」页签）在**真机**上按同一份可勾选清单跑完，
> 结论直接回填 `plan.md` 的验收清单，失败项登记 `review-findings.md`。
> 事实位：条目与判定口径在 `plan.md`（plan-238 / plan-239）；本文只给「怎么跑、看什么、记在哪」。

---

## 0. 准备（一次性，约 3 分钟）

**用隔离演示工作区跑，全程不碰真实持仓**（`data/` 零接触）：

```bash
# 1) 建隔离演示工作区：虚构持仓 + 占位凭据 + 相对路径上屏（可重复执行，幂等）
.venv/bin/python scripts/make-screenshots.py demo

# 2) 后续所有命令都在演示根下执行（配置/持仓/产物都落在演示目录内）
export INVEST_PROJECT_ROOT="$PWD/docs/tmp/screenshots/demo"
cd "$INVEST_PROJECT_ROOT"

# 3) 记下起始状态，作为「文件未被改写」的比对基线
ls -l --time-style=full-iso data/holdings/            # 记录 演示持仓.xlsx 的 mtime/大小
sha256sum data/holdings/演示持仓.xlsx | tee /tmp/accept-before.sha
```

启动入口（两条动线分别用）：

| 动线 | 命令 | 说明 |
|:--|:--|:--|
| TUI | `cd "$INVEST_PROJECT_ROOT" && ../../../../.venv/bin/python src/python/tui/tui.py` | 主菜单 → `[U]` 进入持仓录入 |
| Web | `cd "$INVEST_PROJECT_ROOT" && ../../../../.venv/bin/python src/python/web/server.py --port 8010` | 浏览器打开 `http://127.0.0.1:8010/#holdings` |

> 路径前缀视你所在目录而定：更稳的写法是先 `cd` 回仓库根再用绝对路径
> `.venv/bin/python "$INVEST_PROJECT_ROOT/src/python/tui/tui.py"`。

**回滚与清理**：验收全程只写演示目录；结束后 `rm -rf docs/tmp/screenshots/demo` 即恢复原状。
若临时要拿真实持仓试，先手工复制一份 `.xlsx` 到演示目录，别直接指真实文件。

## 1. TUI 动线（plan-238，六条）

逐条执行、逐条勾选。每条都记「证据」：屏显关键行 / 命令输出 / `sha256sum` 或 `stat` 结果。

### 1.1 进入与列持仓
- 操作：主菜单按 `[U]` → 面板内按 `1`（别名 `L`）列持仓
- 判定：① 键位提示齐全（`1/L 列持仓`、`2/P 买入`、`3/S 卖出`、`4/W 保存`、`5/U 撤销`、`6/C 继续上一笔`、`0 返回`）；
  ② 按账户分块列出，块内为「名称 / 代码 / 份额 / 每份成本」；③ 录入未保存的行行首标红 `*` 且底部有图例
- 证据：`[ ] 勾选` ｜ 屏显摘录：__________

### 1.2 场内买入
- 操作：`2`（`P`）→ 选账户 → 选/填标的（演示持仓的场内品种，如 `510300`）→ 填份额、价格（可留空取当前行情）、交易日
- 判定：① 单笔仅回显「共 N 笔待保存」，不回写文件；② `sha256sum` 与 §0 基线一致（文件未动）
- 证据：`[ ] 勾选` ｜ 回显行：__________ ｜ sha 对比：一致 / 不一致

### 1.3 场外买入（两种口径）
- 操作：`2` → 选一只场外基金（演示持仓里的 `C` 类基金），分别按「只填申购金额」与「填份额」各录一笔
- 判定：① 按金额口径时份额 = 金额 ÷ 该交易日官方净值；② 当日净值未公布时本笔**不成立**并提示改用另一口径；
  ③ `3`（`S`）卖出同样可按份额录入，超额卖出应被拒
- 证据：`[ ] 勾选` ｜ 提示原文：__________

### 1.4 继续录上一笔
- 操作：录完一笔后选 `6`（`C`）
- 判定：① 跳过账户与标的选择、只重填份额/价格/交易日；② 未录过任何一笔时该菜单项不出现
- 证据：`[ ] 勾选` ｜ 屏显：__________

### 1.5 撤销与退出守卫
- 操作：`5`（`U`）连续撤销到空；再录一笔后按 `Esc`（或 `0`）
- 判定：① 撤销逐笔回退、空后提示已无变更；② 退出守卫三选一（保存后退出 / 丢弃退出 / 继续编辑），**默认落在「继续编辑」**
- 证据：`[ ] 勾选` ｜ 守卫提示原文：__________

### 1.6 保存一次输入表达意图
- 操作：`4`（`W`）进入保存，依次走四条路径：先 `0` 取消（草稿保留）→ 再回车（写入 + 记流水）→ `n`（只写持仓不记流水）→ `2`（丢弃草稿）
- 判定：① `0` 取消后草稿仍在且文件未动；② 回车写入后生成 `.bak`、回读校验通过、提示含备份文件名；
  ③ `n` 路径不写「交易流水」页签；④ `2` 丢弃后文件仍与基线一致
- 证据：`[ ]` 四条路径各自结果：__________ ｜ `.bak` 文件名：__________

## 2. Web 动线（plan-239，六项）

页面：`http://127.0.0.1:8010/#holdings`（浏览器打开「持仓录入」页签）。

### 2.1 页签加载
- 判定：① 显示持仓文件名与账户/条数，与 `data/holdings/演示持仓.xlsx` 一致；② 页签内有「未保存的变更不会写入文件」提示
- 证据：`[ ] 勾选` ｜ 条数：______

### 2.2 表单口径
- 操作：选账户 + 标的 → 填份额/金额 → 点「加入变更清单」，再加第二笔
- 判定：① 加入后**保留账户与标的**、只清空份额/金额；② 清单内每笔可「移除」
- 证据：`[ ] 勾选` ｜ 屏显：__________

### 2.3 清空清单
- 判定：① 点「清空清单」有二次确认；② 取消后清单不变；③ 确认后清单空且**持仓文件字节不变**（`sha256sum` 一致）
- 证据：`[ ] 勾选` ｜ sha 对比：一致 / 不一致

### 2.4 保存自动预览
- 操作：清单非空时点「预览写回结果」→ 再点「确认写入持仓文件」
- 判定：① 预览显示写回后条数与「新增/更新/移除」计数 + 逐笔清单 + `.bak` 提示，且此时文件未变；
  ② 确认框自动带一次预览结果；③ 写入成功提示含备份文件名
- 证据：`[ ] 勾选` ｜ 预览计数：新增__ 更新__ 移除__ ｜ 备份名：__________

### 2.5 空态禁用与流水记忆
- 判定：① 清单为空时「预览 / 写入 / 清空」按钮禁用、预览框隐藏；② 勾上「同时记入交易流水」后刷新页面，勾选状态仍保留（首次进入默认勾选）
- 证据：`[ ] 勾选` ｜ 刷新后状态：保留 / 复原

### 2.6 并发闸门（`HOLDINGS_STALE`）
- 操作：页面加一笔但**先不写**，在另一个终端改写文件 mtime 或另存一份同名文件
  （`touch data/holdings/演示持仓.xlsx` 或 `cp` 一份覆盖），再点「确认写入」
- 判定：① 提示 `HOLDINGS_STALE`（文件已被其他程序修改）；② 总览自动刷新为最新内容；③ 原清单不静默覆盖
- 证据：`[ ] 勾选` ｜ 提示原文：__________
