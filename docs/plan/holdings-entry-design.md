# 持仓录入（迭代设计）

> 关联任务：`plan-238`（TUI 渠道）、`plan-239`（WEB 渠道）。
> 本文是该功能的设计与规则事实位；`plan.md` 只保留任务号与一句简述。

## 1. 目标与边界

在 TUI / WEB 两个渠道在线修改**持仓信息文件**并保存，免去「手改 Excel → 重新读取」的往返。两个渠道共用同一编解码层（`holdings_editor`）与净值层（`nav_lookup`）。

边界：

- 只改持仓主表四列（名称 / 代码 / 持仓份额 / 每份成本）与可选「交易流水」页签；不碰报告产物、缓存与其他配置。
- 不引入新的数据源：场外净值走既有历史净值链。
- 不做历史交易回放、不做费用精算（申购费/赎回费不入成本价，见 §4.4）。

## 2. 交互设计（TUI）

### 2.1 入口与二级菜单

首页独立分组 `持仓维护`，仅含一项：`[U] 持仓录入（买入 / 卖出 / 保存）`。

二级菜单（编号为主入口，方括号内为字母别名）：

```
  ── 持仓录入 ──
  文件：个人投资持仓信息.xlsx
  [!] 2 笔变更待保存（按 4 保存才写入文件）
    1. [L] 查看持仓（含未保存变更）
    2. [P] 录入买入
    3. [S] 录入卖出
    4. [W] 保存到持仓文件
    5. [U] 撤销上一笔
    0. 返回主菜单
```

键位约定：

- 一级键 `U`（Update holdings），独立成「持仓维护」组；该组只承载持仓维护，与「数据与查看」（缓存刷新/清理）分开。
- 二级编号 `1`~`5` 为主入口，字母为别名（`L` 查看 / `P` 买入 / `S` 卖出 / `W` 保存 / `U` 撤销）。
- 标签形态统一「动词 + 对象」；「查看持仓」额外标注「含未保存变更」，以区分文件已有内容。

### 2.2 动作与写盘边界

| 键 | 动作 | 是否写文件 |
|---|---|---|
| `1` / `L` | 按账户分块列出现持仓；**本次未保存的行行首标红 `*`**（账户标题同标），底部给图例，无 `*` 即已落盘 | 否 |
| `2` / `P` | 录入一笔买入（只进内存变更清单） | 否 |
| `3` / `S` | 录入一笔卖出（只进内存变更清单） | 否 |
| `4` / `W` | 回显本次全部变更 → 询问是否记流水 → 确认 → 原子写回 → 回读校验 | **是** |
| `5` / `U` | 撤销本次最后一笔（以文件为基线重放剩余变更） | 否 |
| `0` | 返回主菜单；有未保存变更时三选一：保存后退出 / 丢弃退出 / 继续编辑 | 否 |

`Esc` 与 `0` 走同一出口：退出面板后若有未保存变更，统一进入上述三选一，默认「继续编辑」（安全侧）。

### 2.3 录入流程

1. **选账户**：编号选已有账户；直接输入文本则以该名新建账户（拒绝含路径分隔符者）。
2. **选标的**：编号选账户内已有持仓；`N` 输入新代码（6 位数字校验）→ 名称自动带出，取不到再手输。卖出只能选已有持仓。
3. **份额 / 价格 / 交易日**（见 §3、§4）。
4. **单笔回显**（账户/方向/标的/份额/价格/交易日）→ `(y/N)` 确认 → 加入变更清单。
5. 可连续录入多笔；`4` 一次写回。

### 2.4 保存（`4` / `W`）的确认内容

1. 逐笔回显：方向、名称（代码）、份额、价格、交易日、账户。
2. 每个受影响账户保存后的持仓条数（供核对保存结果）。
3. `是否同时记入「交易流水」页签？(y/N)`，默认 N。
4. `确认写入持仓文件？(y/N)`，默认 N。
5. 写前两道闸门（§5.2）→ 备份 → 原子写回 → **回读校验**（重读文件逐行比对份额/成本，不一致即报错并保留变更）→ 成功提示 + 备份文件名。

## 3. 品种与价格

| 品种 | 判定 | 成交价 | 交易日 |
|---|---|---|---|
| 场内（A 股 / ETF / LOF / 港股通） | `price_kind(...) == exchange`（复用 `core/code_utils` 的资产类型判定，不另立前缀知识） | **必填**；回车 = 取当前行情，取不到再手填 | 回车 = 今天 |
| 场外（场外基金） | 其余 | 可手填；**留空 = 按交易日取官方净值** | **必填**，回车 = 今天 |

场外净值取数与降级（`fetcher/nav_lookup.py`）：

- 走既有历史净值链 `history_fund_otc`（多 provider + 缓存），不新增网络源。
- 当日无净值（非交易日 / 净值未发布）→ 取**该日之前最近一个净值日**，并如实回显实际采用的净值日期，需用户 `(y/N)` 确认。
- 全链路取不到 → 该笔标失败：允许手填价格或放弃该笔；**不得**用 0 价或估算净值记账。

### 3.1 录入期校验（不静默放行）

| 校验 | 触发 | 处理 |
|---|---|---|
| 品种歧义 | `00` 开头且名称不含基金特征词（`ambiguous_price_kind`） | 先按行情源反推（`price_kind_from_quote`：`eastmoney`/`sina_fund` → 场外，其余行情源 → 场内）；仍不确定则问一次「1=场内证券 2=场外基金」，取消即放弃本笔 |
| 价格量级 | 录入价与参考价（场内当日行情 / 场外该交易日净值）偏离 > 20% | 提示「像小数点位置错？」，需确认才继续 |
| 重复提交 | 与本次已录入一笔的账户/代码/方向/份额/价格/交易日完全相同 | 需确认才再录一笔（防连按回车） |

参考价复用录入过程中已取到的行情/净值，不额外发起取数。

## 4. 场外买入的两种录入口径

场外申购的份额要等 T 日官方净值公布后才能确定：T 日当天只能给金额。

### 4.1 按金额（默认）

份额 = 申购金额 / 该交易日官方净值。净值未公布 → **本笔不予成立**，提示「请于净值公布后再录入（亦可改选按份额录入）」。

### 4.2 按份额

仅在该交易日净值已可用时成立（净值作为每份成本）；取不到才允许手填价格。

### 4.3 场外卖出

持有份额已知，只按份额录入；成本价来自交易日净值（取不到则手填或放弃）。

### 4.4 费用口径

成本价 = 交易日官方净值，**不含申购费/赎回费**；费用精算不在本功能范围（如需计入应在后续任务中作为独立字段设计，不得悄悄折进净值）。

## 5. 写回契约

### 5.1 结构与范围

- 主表四列就地重写（表头保留）；账户 = 工作表名，账户顺序 = 工作簿内工作表顺序，新账户追加在末尾。
- 非持仓页签（交易流水 / 分红流水 / 任意自定义页签）原样保留；新账户名若与既有非持仓页签同名 → 拒绝保存并提示改名。
- 可选追加「交易流水」行（日期 / 代码 / 操作 / 份额 / 价格，存在「费用」列时补 0）；既有流水页签表头不合契约 → 拒绝保存（不静默跳过）。
- 落盘经 `core/atomic_write.write_bytes_atomic`（同目录临时文件 + `os.replace`），不存在半写状态。

### 5.2 写前两道闸门

1. **文件未被他人改动**：保存前比对 mtime 与载入时基线，不一致 → 拒绝写入并提示重新载入（防止覆盖用户在 Excel 里的手改）。
2. **备份**：写前以原子复制生成同目录 `.bak`（单槽轮转）；备份失败仍继续但如实告知。

### 5.3 成本口径

- 买入：`新成本 = (原份额 × 原成本 + 买入份额 × 买入价) / 新份额`（份额加权平均）。
- 卖出：保留原每份成本，只减份额；份额归零移除该行；卖出份额超过持有量 → 拒绝该笔。
- 落盘精度：份额 4 位、成本 6 位（吸收加权平均除不尽余数）。

## 6. 模块与触点

| 层 | 文件 | 职责 |
|---|---|---|
| 编解码 | `src/python/core/holdings_editor.py` | `HoldingsBook` / `TradeIntent` / `price_kind` / `load_book` / `apply` / `save`；两渠道共用，无网络、无交互 |
| 净值 | `src/python/fetcher/nav_lookup.py` | `resolve_nav_on_trade_date`（日期→净值）、`resolve_purchase_shares`（金额→份额） |
| TUI 外壳 | `src/python/tui/handlers_holdings.py` | 二级菜单（编号为主、字母别名）、选账户/标的、录入会话、保存确认 |
| 菜单接线 | `src/python/tui/tui_menu.py` + `tui.py` | `MENU_ITEMS` 加 `U` 并独立成「持仓维护」组，`_bind_callbacks` 绑定 |

WEB（`plan-239`）直接复用前两层：表单只产出 `TradeIntent`，保存仍走 `HoldingsBook.apply/save`，不得各自实现一份写入逻辑。

## 9. WEB 渠道

- **页签**：工作台「持仓录入」（与 TUI `[U]` 同一套编解码与校验），接口 `GET /api/holdings`、`POST /api/holdings/preview`、`POST /api/holdings/save`。
- **表单字段**：账户（下拉 + 新建）、标的（已有列表 / 输入代码 + 名称）、品种（可显式选场内/场外，00 重叠区必选）、方向、份额或申购金额（场外买入）、价格（留空取行情或交易日净值）、交易日。
- **变更清单只在浏览器侧**：服务端每次用清单重放内存副本，不引入进程级会话状态；预览不落盘。
- **写回**：与 TUI 同口径 —— mtime 闸门（他人改动 → 409 `HOLDINGS_STALE`）、`.bak` 备份、原子写、回读校验、可选记入交易流水。
- **差异摘要**：预览返回写回后的持仓与「新增 / 更新 / 移除」计数，并标出本次未保存的行。
