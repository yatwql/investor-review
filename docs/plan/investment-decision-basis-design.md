# 迭代设计：决策依据章与 LLM 章职责切分

> 关联：`plan.md` → `plan-242`（讨论稿）· 讨论稿 [`investment-decision-quality.md`](./investment-decision-quality.md) 的「章节归属结论」
> 状态：设计稿（未实施；实施前须先完成讨论稿待验证清单 V1~V7 的至少 V1/V3）
> 红线：本稿为设计说明，不改代码、不改配置、不改提示语。

## 1. 定位

把报告的「决策相关内容」拆成两章，职责不重叠：

| 章 | 键 | 性质 | 可控性来源 |
|:---|:---|:---|:---|
| 「决策依据」 | `decision_basis` | 纯规则 / 确定性，**零 LLM 生成** | 可回测、可追责、可单测 |
| 「LLM 分析」 | 既有 `llm` 章 | 解读 / 论辩 / 反方证据 | 只能靠提示语与自检约束 |

**为什么必须拆**（讨论稿「章节归属结论」）：讨论稿查出的 5 条结构性事实（信号零区分度、估值口径丢失、
纪律规则结构偏空、结算频率与执行回执缺失、无硬性风险约束）没有一条能靠改措辞解决；
把它们塞进 LLM 章会让读者无法区分「模型推断」与「规则硬约束」。

## 2. 两章的输出契约（草案）

### 2.1 决策依据章（`decision_basis_data`）

```json
{
  "available": true,
  "signals": [
    {"name": "估值分位", "direction": "bearish", "basis": "price_proxy", "samples": 365,
     "discrimination": "low", "note": "价格分位代理，仅参考，不进方向轴"}
  ],
  "risk_budget": {
    "single_max_pct": 0.20, "single_current_pct": 0.31, "breached": true,
    "industry_max_pct": 0.30, "industry_current_pct": 0.42, "breached": true,
    "max_drawdown_pct": -0.10, "current_drawdown_pct": -0.18, "breached": true
  },
  "discipline": [
    {"code": "022365", "rule": "止损线 -15%", "value": -10.88, "distance_pct": 4.12,
     "regime_note": "下跌段：单点阈值触发需叠加趋势确认"}
  ],
  "confidence": {"level": "low", "reason": "有效信号 2/5，其中 1 项为价格代理"},
  "settlement": {"window": [5, 20], "recent": [{"date": "2026-10-27", "n": 6, "excess": 0.0018}]}
}
```

**硬约束**：
- 任何字段的数值必须来自确定性计算（信号账本 / 持仓 / 配置），**不得由 LLM 生成或改写**。
- `basis`（真实估值 / 价格代理）、`samples`、`discrimination` 三字段为**必填**——缺一即视为该信号不可进方向轴。
- `confidence` 由规则强度与规则冲突仲裁给出（如「有效信号数 < 3 或存在口径代理 → low」），**不是模型自评**。

### 2.2 LLM 章（解读层契约）

- **删除**「必须给出方向性判断」类要求（`prompts_action.py:337` 现文本）；
- **新增**三项强制项：反方证据、失效条件、下一个观察指标；
- 「必须引用具体品种」开口子：允许「不对具体品种动手 + 说明理由」；
- 新增置信度分级要求，且**只能引用决策依据章的 `confidence`**，不得自行升级。

## 3. 与既有架构的衔接

| 关注点 | 做法 |
|:---|:---|
| 章节注册 | 在 `core/report_section_registry.py` 增 `decision_basis`（`type="always"` 或独立开关，待定），编号插在「行动建议」之后 |
| 双端渲染 | HTML partial + Excel 页签各一，数据同源（`pipeline_data["decision_basis_data"]`） |
| 功能开关 | 建议独立开关 `decision_basis`（默认**开**：它是纯事实，不增加风险） |
| 与「行动建议」章的关系 | 行动建议保留（算法建议）；决策依据提供**判断材料与约束状态**，两者不合并 |
| 降级 | 任一块数据缺失 → 该块显示「数据不足」占位，不隐藏整章（与既有降级口径一致） |

## 4. 落地顺序（依赖讨论稿 V 清单）

1. **前置**：V1（20/60 日视界结算）与 V3（估值双口径区分度）——否则 `discrimination` 字段无数据可填。
2. 章骨架：注册表 + 双端渲染 + 空态（不接真实数据，先跑通契约）。
3. 逐块接入：置信度分级 → 风险预算 → 纪律明细 → 结算摘要 → 信号清单。
4. LLM 章改造（提示语 P1/P2/P5）——**必须在新章数据可用之后**，否则模型只能在空材料上改措辞。
5. 对照观察：分批各取 20 次运行，比较建议构成（方向分布、置信度分布）与 20 日结算结果。

## 5. 验收

- 决策依据章所有字段可追溯到确定性来源（单测断言「无 LLM 参与」）。
- 信号缺 `basis`/`samples`/`discrimination` 时**不进方向轴**（负向用例）。
- LLM 章输出不出现无条件方向陈述（提示语契约测试）。
- 连续 20 次运行后，`confidence=low` 的运行占比与建议方向分布有记录可对比。

## 6. 风险与回滚

| 风险 | 缓解 |
|:---|:---|
| 新章与「行动建议」章内容重复、用户困惑 | 明确分工：行动建议=算法动作，决策依据=材料与约束；文案互引 |
| `discrimination` 需回测才可信，早期只能用先验 | 初版标「先验，未回测」，回测完成后更新 |
| LLM 章转为解读层后「没结论」被用户视为退步 | 决策依据章承担「结论」职责；LLM 章定位为「为什么与什么时候会错」 |
| 回滚 | 两处独立开关，可单独关闭；数据结构不删除，只隐藏渲染 |
