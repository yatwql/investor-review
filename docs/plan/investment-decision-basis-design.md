# 迭代设计：决策依据章与 LLM 章职责切分

> 关联：`plan.md` → `plan-242`（讨论稿）· 讨论稿 [`investment-decision-quality.md`](./investment-decision-quality.md) 的「章节归属结论」
> 状态：**设计稿定稿 v1**（50 轮复盘完成；未实施；实施前须先完成讨论稿待验证清单 V1~V7 的至少 V1/V3）
> 红线：本稿为设计说明，不改代码、不改配置、不改提示语。

## 1. 定位

把报告的「决策相关内容」拆成两章，职责不重叠：

| 章 | 键 | 性质 | 可控性来源 |
|:---|:---|:---|:---|
| 「决策依据」 | `decision_basis` | 纯规则 / 确定性，**零 LLM 生成** | 可回测、可追责、可单测 |
| 「LLM 分析」 | 既有 `llm` 章 | 解读 / 论辩 / 反方证据 | 只能靠提示语与自检约束 |

**为什么必须拆**（讨论稿「章节归属结论」）：讨论稿查出的 5 条结构性事实（信号零区分度、估值口径丢失、
纪律规则结构偏空、结算频率与执行回执缺失、无硬性风险约束）没有一条能靠改措辞解决；
把它们塞进 LLM 章会让读者无法区分「模型推断」与「规则硬约束」。

## 2. 两章的输出契约（草案）

### 2.1 决策依据章（`decision_basis_data`）

```json
{
  "available": true,
  "signals": [
    {"name": "估值分位", "direction": "bearish", "basis": "price_proxy", "samples": 365,
     "discrimination": "low", "note": "价格分位代理，仅参考，不进方向轴"}
  ],
  "risk_budget": {
    "single_max_pct": 0.20, "single_current_pct": 0.31, "breached": true,
    "industry_max_pct": 0.30, "industry_current_pct": 0.42, "breached": true,
    "max_drawdown_pct": -0.10, "current_drawdown_pct": -0.18, "breached": true
  },
  "discipline": [
    {"code": "022365", "rule": "止损线 -15%", "value": -10.88, "distance_pct": 4.12,
     "regime_note": "下跌段：单点阈值触发需叠加趋势确认"}
  ],
  "confidence": {"level": "low", "reason": "有效信号 2/5，其中 1 项为价格代理"},
  "settlement": {"window": [5, 20], "recent": [{"date": "2026-10-27", "n": 6, "excess": 0.0018}]}
}
```

**硬约束**：
- 任何字段的数值必须来自确定性计算（信号账本 / 持仓 / 配置），**不得由 LLM 生成或改写**。
- `basis`（真实估值 / 价格代理）、`samples`、`discrimination` 三字段为**必填**——缺一即视为该信号不可进方向轴。
- `confidence` 由规则强度与规则冲突仲裁给出（如「有效信号数 < 3 或存在口径代理 → low」），**不是模型自评**。

### LLM 章契约 LLM 章（解读层契约）

- **删除**「必须给出方向性判断」类要求（`prompts_action.py:337` 现文本）；
- **新增**三项强制项：反方证据、失效条件、下一个观察指标；
- 「必须引用具体品种」开口子：允许「不对具体品种动手 + 说明理由」；
- 新增置信度分级要求，且**只能引用决策依据章的 `confidence`**，不得自行升级。

## 呈现形态对照 呈现形态两案对照（推荐先做形态 A）

「决策依据」有两种落地位置，**数据契约（`decision_basis_data`）完全相同**，只是渲染位置不同。

### 形态 A：放入「行动建议」章头部（推荐先做）

```
行动建议（章，key=action，序号 7）
└─ ▸ 判断依据  [默认折叠]
     summary：有效信号 2/5 · 集中度超限（纳指系 42%）· 置信度：低
     内容：信号清单（口径/样本/区分度）｜风险预算 vs 上限｜纪律触发与距阈值｜置信度理由｜近 N 条结算
```

| 项 | 评价 |
|:---|:---|
| 改动面 | **小**：复用行动章既有「章内块」模式（历史决策复盘 / 景气度诊断 / 市场情绪三块即按此挂，传 `None` 即不渲染）；HTML 用既有 `details.section-fold`，Excel 用 `write_data_row` 顺序写入 |
| 注册表 | **零改动**（不新增 key、不改 `report_section_order`、序号不顺延） |
| 开关 | 复用 `enable_action`；另可选子开关 `decision_basis_in_action`（默认开） |
| 优点 | 判断链连贯（先看依据再看动作）；与「行动建议」同生共死，语义自洽 |
| 代价 | ① 章节名不变，可发现性弱 ② 章首变重（默认折叠 + 一句话 summary 缓解）③ 关掉行动章即失去依据 |

### 形态 B：独立章节（`decision_basis`，序号插在 action 之后）

| 项 | 评价 |
|:---|:---|
| 改动面 | **大**：注册表新增 key + 序号顺延 + `report_section_order` 同步 + 独立开关 + 双端 partial/页签 |
| 优点 | 可独立开关与排序；可被单独引用；不受 `enable_action` 影响 |
| 代价 | 与行动建议内容可能重复，需文案互引；注册/顺序/配置三处同步易漂（已有防漂移测试兜底） |

### 选型结论

**先做形态 A**，理由是成本低、可逆、判断链连贯；若后续观测到「用户频繁单独读依据」或需要独立排序，再升级为形态 B——
**数据契约与渲染函数可原样复用**，升级只涉及注册表与模板位置。

## 3. 与既有架构的衔接

| 关注点 | 做法 |
|:---|:---|
| 章节注册 | 在 `core/report_section_registry.py` 增 `decision_basis`（`type="always"` 或独立开关，待定），编号插在「行动建议」之后 |
| 双端渲染 | HTML partial + Excel 页签各一，数据同源（`pipeline_data["decision_basis_data"]`） |
| 功能开关 | 建议独立开关 `decision_basis`（默认**开**：它是纯事实，不增加风险） |
| 与「行动建议」章的关系 | 形态 A 下作为其**章内块**（不合并语义、只共用容器）；形态 B 下为独立章 |
| LLM 章节开关的联动 | **零联动**：本块只读 `signal_ledger` / 持仓 / 配置 / `decision_ledger`，关掉任一 LLM 模块或整章 LLM 都不影响；LLM 章写「请引用决策依据」时，若该块缺失则**该段提示词不注入**（不阻断 LLM、不出占位噪音） |
| 章内块降级 | 任一数据块缺失 → 该块「数据不足」占位，不隐藏整块容器；置信度由有效信号数与口径质量决定，**不因 LLM 关闭而升级** |
| 降级 | 任一块数据缺失 → 该块显示「数据不足」占位，不隐藏整章（与既有降级口径一致） |

## 4. 落地顺序（依赖讨论稿 V 清单）

1. **前置**：V1（20/60 日视界结算）与 V3（估值双口径区分度）——否则 `discrimination` 字段无数据可填。
2. **首版骨架（形态 A）**：行动章内块容器 + 折叠摘要 + 双端空态；只接 **3 项**——置信度、信号清单、风险预算（无网络依赖，不做阶段计时、不新增缓存类型）。
3. **次版**：补纪律明细块（上下文与该不该执行的规则化说明）。
4. **末版**：补结算摘要（最近 5 个批次）。
5. LLM 章改造（提示语 P1/P2/P5）——**必须在依据块数据可用之后**，否则模型只能在空材料上改措辞。
6. 对照观察：分批各取 20 次运行，比较建议构成（方向分布、置信度分布）与 20 日结算结果。
7. 实施前登记 `R-OUT` 需求条目与语义命名表条目。

## 5. 验收

- 决策依据章所有字段可追溯到确定性来源（单测断言「无 LLM 参与」）。
- 信号缺 `basis`/`samples`/`discrimination` 时**不进方向轴**（负向用例）。
- LLM 章输出不出现无条件方向陈述（提示语契约测试）。
- 连续 20 次运行后，`confidence=low` 的运行占比与建议方向分布有记录可对比。

## 6. 风险与回滚

| 风险 | 缓解 |
|:---|:---|
| 新章与「行动建议」章内容重复、用户困惑 | 明确分工：行动建议=算法动作，决策依据=材料与约束；文案互引 |
| `discrimination` 需回测才可信，早期只能用先验 | 初版标「先验，未回测」，回测完成后更新 |
| LLM 章转为解读层后「没结论」被用户视为退步 | 决策依据章承担「结论」职责；LLM 章定位为「为什么与什么时候会错」 |
| 章首过重（形态 A） | 默认折叠 + summary 一句话结论；只放一块，详情引用既有章节数据 |
| 可发现性弱（形态 A） | 块标题固定为「判断依据」，并在行动章标题副行补「依据 · 信号 · 纪律 · 调仓 · 归因」 |
| 回滚 | 形态 A 下由 `decision_basis_in_action` 子开关关闭（默认开）；形态 B 下由独立开关关闭；数据结构不删除，只隐藏渲染 |

## 附录 A：设计稿复盘（50 轮）

> 格式：**质疑 / 证据 / 结论 / 修改**。证据来源限于代码事实、既有机制、讨论稿结论；`读代码` 类均已核。
> 本轮只打磨设计稿，不实施。

### 第 1 轮：形态 A 与行动章现有 7 块的关系
**质疑**：加第 8 块会不会让行动章失焦？
**证据**：`section_block_registry` 的 `action` 已含 7 块（再平衡/纪律/调仓/归因/历史决策复盘/景气度/市场情绪），其中后三块为「可选增强」。HTML 侧已有 `details.section-fold` 折叠模式（`action_section.html:28`）。
**结论**：可以加，但**必须折叠 + 一句话 summary**，且只加**一块**（内含 5 个紧凑小节），不新增 5 个平级块。
**修改**：呈现形态对照 形态 A 明确「只加一块」。

### 第 2 轮：内容与「交易纪律」块重复
**质疑**：行动章已有「交易纪律」块，依据块再列纪律触发是否重复？
**证据**：既有纪律块只给「是否触发 + 当前值」；依据块要给「距阈值 + 该规则在当前市场状态下是否应机械执行」。
**结论**：**不重复但要互引**：依据块只做「上下文与解释」，动作明细仍归纪律块。
**修改**：呈现形态对照 增补「纪律块：动作与阈值；依据块：上下文与该不该执行」。

### 第 3 轮：Excel 侧没有 HTML 的折叠
**质疑**：HTML 可 `details` 折叠，Excel 页签怎么控制章首长度？
**证据**：`excel_writer.write_data_row` 顺序写入，无折叠概念；行动页签已 5 列宽。
**结论**：Excel 侧用**行数预算**（≤ 12 行）+ 明细引用既有页签，不铺开五个小节。
**修改**：「与既有架构的衔接」节补「Excel 行数预算 ≤12 行，明细引用纪律/集中度页签」。

### 第 4 轮：`confidence` 由规则给，规则冲突怎么办
**质疑**：多个信号互相矛盾时置信度怎么定？
**证据**：现有系统无仲裁层；讨论稿第 15 轮已指出系统无置信度概念。
**结论**：引入**最小仲裁规则**：有效信号数 ≥3 且方向一致 → mid；方向分裂 → low；全部为口径代理 → low + 原因。**不做加权投票**（权重无依据）。
**修改**：输出契约补 `confidence.reason` 枚举（信号不足 / 方向分裂 / 全为代理 / 正常）。

### 第 5 轮：`discrimination` 字段没有数据怎么办
**质疑**：讨论稿 V2/V3 尚未回测，字段无值。
**证据**：讨论稿待验证清单明确 V1/V3 未做。
**结论**：初版填 `"unverified"` 并在页面显示「未回测」，**不得**用先验主观填 low/high。
**修改**：输出契约允许 `unverified`；「验收」节补「未回测必须显式标注」。

### 第 6 轮：形态 A 的开关粒度
**质疑**：用户只想关依据块、保留动作，怎么关？
**证据**：`enable_action` 是章级开关，无块级开关先例（块多由数据是否注入控制）。
**结论**：**不新增块级开关**——沿用既有口径「数据不注入即不渲染」，由配置 `decision_basis.enabled`（默认 true）控制注入。
**修改**：「与既有架构的衔接」节把子开关改为 `decision_basis.enabled` 配置项。

### 第 7 轮：与 LLM 章的引用是否成环
**质疑**：LLM 章引用依据块，依据块又可能引用 LLM 结论（如结算摘要里的建议来源），会否成环？
**证据**：结算摘要只读 `decision_ledger`（记录的是建议，不是 LLM 文本）。
**结论**：不成环；依据块**禁止**读任何 LLM 输出文本。
**修改**：2.1 硬约束补「禁止读取 LLM 产出文本（只读账本字段）」。

### 第 8 轮：数据量增长后章首会不会膨胀
**质疑**：结算摘要「近 N 条」N 取多少？
**证据**：当前 27 条结算、9 个批次；N 太大在章首无意义。
**结论**：N 固定为「最近 5 个批次」，超出的看既有「历史决策复盘」块。
**修改**：输出契约 `settlement.recent` 上限 5。

### 第 9 轮：风险预算与「再平衡信号」块重复
**质疑**：行动章已有再平衡信号（单品占比超警戒线），依据块再列风险预算重复？
**证据**：再平衡信号是「超线即提示」，依据块要的是「上限配置 vs 当前值 vs 是否超限」的全景。
**结论**：依据块只展示**配置上限与当前值**，不重复给动作；动作归再平衡块。
**修改**：呈现形态对照 分工表补一行。

### 第 10 轮：形态 A 升级形态 B 的成本
**质疑**：先 A 后 B 是否要重写？
**证据**：两者差异仅在「注入点与渲染位置」，数据契约与渲染函数可复用。
**结论**：**升级只涉及注册表 + 模板位置 + 章节号**，无需重写契约与计算。
**修改**：呈现形态对照 选型结论保留该判断。

### 第 11 轮：`basis` 字段的取值范围
**质疑**：口径标记只有「估值 / 价格代理」两类吗？
**证据**：信号源还有资金流向、温度、尾部风险、风格、因子目录。
**结论**：`basis` 枚举应为 `valuation_real` / `price_proxy` / `rule_based` / `stat_model`，并允许 `unknown`（未知即不可进方向轴）。
**修改**：输出契约补枚举。

### 第 12 轮：块内是否需要图表
**质疑**：信号区分度、风险预算是否会配图？
**证据**：行动章现有块均为表格，无图表；`DESIGN.md` 要求图表走既有图表设施。
**结论**：**首版不配图**，用表格 + 色标（超限标红），避免引入新图表类型。
**修改**：呈现形态对照 补「首版无图表，超限用既有色标」。

### 第 13 轮：与「历史决策复盘」块的分工
**质疑**：行动章已有「历史决策复盘」（决策跨期反思，默认关），依据块的结算摘要是否重叠？
**证据**：历史决策复盘是实验项（`plan-70` 观察中，默认关）；依据块的结算摘要是**基础事实**（默认开）。
**结论**：不冲突；前者做归因分析，后者只给事实数字。
**修改**：呈现形态对照 补一句分工。

### 第 14 轮：空态文案
**质疑**：全部数据缺失时显示什么？
**证据**：`DESIGN.md` 的 Data States 口径要求「数据不足」统一文案，不臆造。
**结论**：整块显示「数据不足（缺 X）」，不进折叠 summary。
**修改**：「验收」节补空态用例。

### 第 15 轮：性能影响
**质疑**：新块会不会增加耗时？
**证据**：数据全部已在内存或账本（`signal_ledger` 读取 299 行、`decision_ledger` 117 行），无网络调用。
**结论**：**可忽略**（毫秒级）；不需新增阶段计时。
**修改**：「落地顺序」节落地顺序补「无网络依赖，不做阶段计时」。

### 第 16 轮：是否需要新缓存
**质疑**：是否要缓存 `decision_basis_data`？
**证据**：源数据均为本地账本/持仓，读取成本极低；缓存反而引入失效问题。
**结论**：**不缓存**，每轮现算。
**修改**：「与既有架构的衔接」节补「不新增缓存类型」。

### 第 17 轮：测试策略
**质疑**：怎么测「零 LLM 依赖」？
**证据**：可断言该函数入参不含 `llm_content`。
**结论**：单测断言「构造函数签名无 LLM 参数 + 输出在 `enable_llm=False` 时与 `True` 逐字节一致」。
**修改**：「验收」节补该用例。

### 第 18 轮：与需求 ID 的关联
**质疑**：是否需要登记需求条目？
**证据**：`requirements.md` 以 R-XXX 编号，报告章节类需求已有 R-OUT、R-PERF 等。
**结论**：实施时需补一条 R-OUT 需求（章节与开关），本稿不预登记。
**修改**：「落地顺序」节补「实施前登记 R-OUT 条目」。

### 第 19 轮：`samples` 的含义
**质疑**：样本量指信号次数还是回测样本数？
**证据**：两者都可称「样本」，易歧义。
**结论**：字段改名为 `n_obs`（信号观测条数）与 `n_backtest`（回测样本），分别可空。
**修改**：输出契约同步。

### 第 20 轮：`discrimination` 的计算口径
**质疑**：区分度用什么指标？
**证据**：讨论稿 LLM 章契约 已定 IC + 分组单调性。
**结论**：字段存 `ic`（数值）与 `monotonic`（布尔），不用 single 标签。
**修改**：输出契约同步。

### 第 21 轮：形态 A 下章节序号是否需要动
**质疑**：加块会否影响 `report_section_order`？
**证据**：块不是章节，`section_block_registry` 与 `report_section_order` 是两套。
**结论**：**不需要动**任何顺序配置。
**修改**：呈现形态对照 明确「零注册表改动」。

### 第 22 轮：用户能否单独导出依据块
**质疑**：形态 A 下用户若想单独看/导出依据怎么办？
**证据**：Excel 侧可另建隐藏页签或追加到行动页签；HTML 侧可锚点跳转。
**结论**：**Excel 放行动页签顶部区域**，不新建页签；HTML 加 `id="decision-basis"` 锚点。
**修改**：呈现形态对照 补导出与锚点。

### 第 23 轮：与「数据源可用性矩阵」的关系
**质疑**：信号缺失是否要在矩阵里体现？
**证据**：矩阵按数据类别列可用性；信号层不是数据类别。
**结论**：无关，不写入矩阵。
**修改**：「与既有架构的衔接」节补一句「不进可用性矩阵」。

### 第 24 轮：是否需要 TUI/CLI 同步
**质疑**：三渠道是否需要一致？
**证据**：行动章在三渠道均有呈现（TUI 报告菜单、CLI 输出）。
**结论**：**CLI/TUI 首版不加**（它们输出精简摘要），仅在 HTML/Excel 呈现；若后续需要，复用同一契约。
**修改**：「与既有架构的衔接」节补渠道范围。

### 第 25 轮：`confidence` 是否会反向影响动作
**质疑**：置信度低是否应阻止给出调仓建议？
**证据**：现行动作由再平衡/纪律规则给出，不受置信度影响。
**结论**：**不阻断**，但动作块头部显示「依据置信度：低」，让用户自行判断；是否阻断留待 V 系列回测后决定。
**修改**：呈现形态对照 补该取舍。

### 第 26 轮：字段命名一致性
**质疑**：`basis` / `discrimination` / `confidence` 是否与既有术语冲突？
**证据**：既有契约用 `available` / `reason` / `source` 等；`confidence` 为新概念。
**结论**：全部下划线小写，且在技术设计「语义命名表」登记（实施时）。
**修改**：「落地顺序」节补「登记语义命名表」。

### 第 27 轮：降级与 `available` 字段
**质疑**：整块是否需要 `available`？
**证据**：行动章其他块均带 `available`。
**结论**：需要，且 `available=False` 时给 `reason`。
**修改**：输出契约已含，补 `reason` 说明。

### 第 28 轮：形态 A 与 `enable_action=False` 的影响
**质疑**：用户关掉行动章，依据也没了，是否合理？
**证据**：依据块服务于「看动作」的场景；但用户可能只想要依据。
**结论**：可接受（形态 A 的已知代价）；若观测到需求，升级形态 B。
**修改**：呈现形态对照 代价列已写明。

### 第 29 轮：与 `plan-70`（决策反思转正）的先后
**质疑**：两者都碰 `decision_ledger`，会否冲突？
**证据**：`plan-70` 是实验项观察中；依据块只读账本事实。
**结论**：无冲突；建议**先做依据块**（纯事实、零风险），`plan-70` 转正另说。
**修改**：「落地顺序」节补该顺序建议。

### 第 30 轮：设计稿是否过度设计
**质疑**：5 个小节是否太多？
**证据**：形态 A 要求「只加一块」，内部小节需控制。
**结论**：**首版只做 3 项**：信号清单（含口径/区分度）、风险预算、置信度；纪律明细与结算摘要**延后**。
**修改**：「落地顺序」节改为三档（首版 3 项 → 次版补纪律 → 末版补结算）。

### 第 31 轮：`n_backtest` 缺失时的显示
**质疑**：回测未做时显示什么？
**证据**：第 5 轮已定 `unverified`。
**结论**：显示「未回测」，且该信号**不进方向轴**。
**修改**：「验收」节补。

### 第 32 轮：块内排序
**质疑**：三小节谁先谁后？
**证据**：读者关心顺序是「结论 → 依据 → 约束」。
**结论**：置信度（结论）→ 信号清单（依据）→ 风险预算（约束）。
**修改**：呈现形态对照 补排序。

### 第 33 轮：一句话 summary 的内容
**质疑**：summary 写什么最有信息量？
**证据**：用户扫一眼要判断「这次建议可信吗」。
**结论**：`有效信号 x/y · 最高风险项 · 置信度z`。
**修改**：呈现形态对照 已给示例，保留。

### 第 34 轮：配色与 DESIGN.md 一致性
**质疑**：超限标红是否合规？
**证据**：`DESIGN.md` 状态色按值给（绿正常/黄注意/红错误），超限属「注意/错误」。
**结论**：超限用既有 warning/danger 语义色，不新增色值。
**修改**：呈现形态对照 补「颜色取 DESIGN.md 语义角色」。

### 第 35 轮：暗色模式
**质疑**：新块是否需要暗色覆盖？
**证据**：DESIGN.md 要求改亮色必须同步暗色覆盖。

### 第 38 轮：形态 B 的章节号顺延影响
