## 1. 目标

把 TUI 中重复出现的四类视觉元素收敛为**一套可机检的显示模式**，避免同类信息在不同面板出现不同颜色/文案/置灰策略：

| 行型 | 目标形态 | 颜色/语义 | 唯一产出点 |
|:--|:--|:--|:--|
| 分组标题 | `── 组名（n/m 开）──`，组间空行 | 蓝 + 粗（结构色）；分组描述本身也是蓝色，不承载状态 | `text_layout.group_heading()` / `switch_panel.format_heading()` |
| 配置项 | `编号. 名称  键名 [状态]*`；键名恒显 | 名称正文色、键名 `DIM`、状态按开关语义；整行不整体着色 | `switch_panel.format_item()` / `[C]` 的 `_format_row()` |
| 开关状态 | `[开启]/[关闭]`（宽/中档）、`[开]/[关]`（窄档） | **开启绿、关闭恒红**；父项关闭/整行置灰时状态字仍红 | `switch_panel.status_text()` |
| 提示/反馈 | `  > ` 输入位；`[OK]/[!]/[ERR]` | 成功绿、告警黄、错误红；正文不加状态色 | `prompt_text.panel_prompt()` / `wrap_prompt` / 反馈常量 |

## 2. 关键决策

1. **状态字与置灰解耦**：`DIM` 只作用于名称/键名/附注；父章节关闭时子项不可切换，但仍以红色 `[关闭]` 显示有效状态，并附「启用本章节后可切换」。不得用「无色」表达关闭。
2. **`*` 只标默认漂移**：`*` 表示当前值与出厂默认不同，不改变状态色；`[开]*` 不是异常。
3. **ANSI 截断必须闭合**：任何含颜色的行在折行/截断后补全转义并以 `RESET` 收尾，避免颜色泄漏到下一行（窄档截断蓝色分组标题曾导致后续章节行整体变蓝）。
4. **分组标题不手写**：业务面板不得拼裸 `── ... ──` 或自行套 `BLUE`；统一走 `group_heading` / `format_heading`，首页、`[C]`、`[S]`、`[G]` 同款。
5. **提示不靠颜色表达动作**：回车默认项、取消项、帮助入口按 `DESIGN-TUI.md` 的提示三段式写全；颜色只做辅助。
