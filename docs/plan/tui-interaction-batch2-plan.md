## 3. `pager` — 分页查看器（本批主体）

### 3.1 现状

三处长输出各自「一次打满 + 按任意键」：日志（最多 200 条，可按级别筛）、数据源健康历史（最近 10 次）、系统自检（逐项 + 修复建议）。窄屏上这些内容远超一屏，闸门只是在补偿「读完前就被下一帧顶掉」。

### 3.2 设计

- `pager.view(title: str, lines: list[str], *, key_reader=None, echo=print) -> None`
- 行数不足一屏（`len(lines) <= rows - 页脚占 2 行`）→ **整段直打并返回**，不加任何击键（保持既有手感，也让管道/日志转存场景不受影响）。
- 非 TTY（`sys.stdout.isatty()` 为假）→ 同样整段直打。
- 否则进分页：每屏 `rows - 2` 行（标题行 + 页脚行固定），页脚固定显示位置与可用键。
- 入口行：标题沿用各面板现有横幅（`最近日志（级别: X）` / `数据源健康历史（最近 10 次）` / 自检报告首行），分页器自己不另造标题样式。

### 3.3 键位矩阵与动作

| 键 | 动作 | 说明 |
|:--|:--|:--|
| `空格` / `↓` / `j` | 下翻一屏 / 一行 | 空格与 ↓ 同屏翻，`j` 走一行（与主菜单 `j/k` 别名同一手感） |
| `↑` / `k` / `b` | 上翻一行 / 一屏 | `b` = back 一屏 |
| `g` / `G` | 跳到首 / 末 | 末屏对齐到底部（不出现半屏空行） |
| `/` | 搜索（行子串） | 回车提交、`Esc` 取消；命中则把该行置顶显示并在页脚标出 `命中 3/17`，再按 `/` 取下一个 |
| `q` / `Esc` / `0` | 退出 | 三个都退，避免与面板「`0` 返回」的肌肉记忆打架 |

搜索**不做**高亮反显：新引入一种颜色语义要动 `DESIGN-TUI` 配色表，收益不抵成本；改为「命中行置顶 + 页脚计数」。

### 3.4 迁移三处

| 位置 | 改动 |
|:--|:--|
| `handlers_log._cmd_view_logs` | 组装好行列表后交给 `pager.view`，删掉尾部 `press_any_key()` |
| `handlers_log._cmd_view_health_history` | 同上 |
| `handlers_log._cmd_run_doctor` | 自检报告整段进分页器（结论行置末页，读完即见） |
| `test_prompt_contract.GATE_WHITELIST` | 白名单删这三项，保留 `handlers_cache._run_cache_update` 与 `report_artifacts._wait_any_key` |

### 3.5 支点：`terminal_rows()`

`text_layout` 只探列宽，没有行数。新增 `terminal_rows(default: int = 24)`：与 `terminal_columns` 同优先级（`os.get_terminal_size()` → `LINES` 环境变量 → 兜底 24），下限 8 行（低于 8 行分页无意义，直接整段直打）。

## 4. 首页 `?` 速查

### 4.1 语义统一原则

面板内 `?` = 「这一屏能按什么」；首页 `?` = 同一句话，只是把「这一屏」换成了主菜单。因此**不新造渲染器**：把 `MENU_ITEMS` 投影成 `PanelItem`（`kind="info"`、`detail` 放该项的一句话说明），直接复用 `prompt_text.keys_help_lines()`；`?键` 沿用在面板里的同一套单项详情格式。

### 4.2 实现要点

- `tui_menu.menu_help_items()`：主菜单 → `PanelItem` 投影（键、标签、`detail` 由分组 + 一句说明组成）。
- `tui.py` 内层循环新增 `?` 分支：渲染完帮助后 `break`（重绘菜单帧），不修改任何状态。
- 首页 `?` 屏的末尾补三行动线提示（「想生成报告按 B / 想改配置按 G / 找不到项按 `/` 筛选」），把速查变成可用入口。

### 4.3 用例

| 文件 | 断言要点 |
|:--|:--|
| `src/test/unit/ui/test_tui_menu_help.py` | 投影出的键集合与主菜单按键一一对应；帮助屏含全部分组标题；`?` 后仍是同一帧（不误触任何动作）；击键基线不变 |
| `test_prompt_contract.py` | 帮助文案不得出现术语表禁用词（复用既有扫描） |

## 5. 环境适配双开关

| 开关 | 行为 | 触点点 |
|:--|:--|:--|
| `TUI_ASCII=1` | 结构线/游标/实验标记/进度块换 ASCII：`─`→`-`、`├`→`|`、`└`→`+`、`▸`→`>`、`⚗`→`*`、`█/░`→`#/.`、`●/○`→`O/o` | `text_layout.SYMBOLS` 单源；`switch_panel` / `status_line` / `handlers_switch` / `progress.print_timing_summary` 四处取用点改查表 |
| `TUI_PLAIN=1` | 关掉原地重绘，走整屏追加（等价非 TTY 分支） | `tui._can_repaint_inplace()` 增加环境判据；`live_status.supported()` 已认此开关 |

**列宽不变**是硬要求：ASCII 替换只换字符不换宽度（`─` 与 `-` 同为 1 列，`▸` 与 `>` 同为 1 列），仓库现有「窄档每行 ≤ 列宽」用例可直接复用为回归。

`TUI_PLAIN` 为一行判据（`can_repaint_inplace` 前置检查），`live_status` 与 `KeyWatcher` 同样认此开关。

`TUI_ASCII` 单独立项：全仓 TUI 层共 103 处分散符号（`─ ├ └ │ ▸ ⚗ █ ░ ● ○ ⤷ ▲ ▼`，遍及 17 个文件），逐处替换并逐一核对「宽度不变」的成本高于本批其余三项之和。立项时先建 `symbols` 单源、再按文件分批迁移，并加一条「TUI 源码不得出现裸符号常量」的机检兜底。

## 7. 顺序、验收与风险

**顺序**：`terminal_rows` → `pager` + 三个查看器迁移 → 环境双开关 → 首页 `?`。前两步合成一个提交（分页器 + 迁移是同一件事），后两步各自一个提交。

**验收（可观察）**：

1. 日志视图超过一屏时出现页脚键位行，空格翻页、`q` 返回；内容不足一屏时与当前行为完全一致（无新增按键）。
2. `investor-review --tui > out.txt` 输出仍与当前逐字节一致（分页器在非 TTY 直打）。
3. 首页按 `?` 出键位速查，再按任意键回菜单，菜单帧内容不变。
4. `TUI_ASCII=1` 下全屏无制表符/圆点类符号，且每行宽度与不设该变量时相同。
5. 击键基线 json 无变更；`按任意键` 白名单只剩 2 项。

**风险**：

| 风险 | 缓解 |
|:--|:--|
| 分页器自成一套键位，与面板 `0/B 返回` 认知冲突 | `q`/`Esc`/`0` 三键都退；页脚常驻键位行；契约明确「只存在于分页视图内」 |
| 搜索置顶打乱「时间序」直觉 | 页脚标出 `命中 3/17`，退出搜索回到原位置（不改变原始行序） |
| 三个查看器改走分页后行数变多（页脚占 2 行） | 窄屏按「列宽折行后再分页」，即以**渲染后行**为单位，不会出现半行 |
| ASCII 替换遗漏个别符号 | `symbols` 单源 + 一条「全仓 TUI 源码不得出现裸制表符常量」的机检（扫 `src/python/tui/*.py` 字面量） |

## 8. 批次边界与后续拆分

`/` 筛选进面板的成本高于本批其余三项之和：面板的帧由**面板自己**调用 `render(nav)` 逐行打印，运行时无法过滤行，要给 `NavState` 增加可见集合、并在 8 个面板的渲染循环里各加一行跳过逻辑，同时统一「筛选态下直达键只对命中项生效」的分派规则（首页已有这套语义，面板侧需实现一遍）。因此本批不含该项，边界如下：

- **第二批**：`pager` + 首页 `?` + 环境双开关。不动面板渲染协议。
- **第三批**：`/` 筛选进面板（`NavState.visible` + 8 面板渲染点 + 分派规则统一）+ 配置面板「可试可退」+ 页头瘦身 + `TUI_ASCII`。

如果希望第二批就带上面板筛选，需要先接受「`NavState` 增加可见集合」这一协议变更，我会另出一份协议变更说明再动手。
